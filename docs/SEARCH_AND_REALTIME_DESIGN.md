# 搜索与实时消息设计

更新时间：2026-10-01

页面、失联及发送前核验的当前共用规则见 [UI_WORKFLOW_RULES.md](UI_WORKFLOW_RULES.md)。
本页保留已有规划；稳定身份端到端导航和所有搜索弹窗仍需 WA-005 验收。

## 成本边界

- 实时消息热路径：Windows 目录变化事件、只读数据库增量查询、游标去重，OCR 为 0。
- 已知会话导航：本地稳定 `wechat_id`、目标类型和场景规划，OCR 默认关闭。
- 页面状态：优先使用导航图标绿色像素和本地头像模板，不识别文字。
- 个性签名：仅固定观察名单的定时资料任务允许 OCR；与收消息、生成草稿和每次回复解耦。
- 异常恢复：只有布局变化、同名冲突或验收任务可显式开启一次 OCR。

## 搜索场景

| 场景 | 可接受目标 | 分区顺序与策略 |
|---|---|---|
| `contacts` | 联系人 | 先进入通讯录，再只接受联系人，不把同名群聊或内容结果计入候选 |
| `groups` | 群聊 | 先进入通讯录，再只接受群聊；没有可靠专用入口时拒绝执行，不猜主搜索位置 |
| `main` | 联系人、群聊、公众号等 | 使用当前微信4.x顺序规划；联系人先于群聊，内容类结果在后；同名高优先级候选存在时禁止直接回车 |

`SearchRouter` 先调用本地数据库规划器，并按目标类型自动选择 `contacts` 或 `groups` 场景。只有目标类型唯一、且前面没有同名高优先级候选时才允许继续；否则在 UI 动作发生前停止。OCR 恢复解析器不假定固定顺序，而是按当前截图中各分区标题的实际纵向顺序分组。

## 实机验收

- 已用 DPAPI 保存的本机密钥只读打开真实 `contact.db` 和 16 个消息分库。
- 已启动 `WindowsDirectoryWatcher` 并执行真实增量游标查询。
- 验收期间 `ocr_calls=0`，`rapidocr_onnxruntime` 未加载。
- 当前微信的 MMUI 在真正后台时会拒绝部分点击；驱动使用短暂焦点租约并在动作结束恢复原前台。搜索未通过焦点/结果验收时，绝不按回车。
- 联系人/群搜索必须从通讯录场景进入；若本地记录与 UI 不一致，返回 `ambiguous_or_unavailable` 或 `ui_target_not_verified`，提示可能已删除、拉黑、改名、退群或本地资料过期。
