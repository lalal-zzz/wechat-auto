# WeChat Auto 后续开发路线图

更新时间：2026-10-01

本文是未来工作的唯一详细清单。`README.md` 只展示摘要，本机忽略的 `PROJECT_STATE.md` 记录运行状态，不随源码发布。事项只有在代码、自动化测试、文档和所列实机验收全部满足后才能标记完成。

## 状态与优先级

| 标记 | 含义 |
|---|---|
| `planned` | 已定义，尚未开始 |
| `blocked` | 有明确外部依赖或缺失输入 |
| `in_progress` | 正在实现，不能作为稳定能力宣传 |
| `verified` | 自动化和指定实机验收均完成 |

优先级为 `P0` 至 `P3`。P0 是安全或数据正确性前置条件；高层功能不得绕过未完成的 P0。

## 0.7.x：当前帧控件识别与运行可靠性

### WA-005 稳定收件人定位、删除状态与发送门禁 — P0 / in_progress

共用规则已落地 [UI_WORKFLOW_RULES.md](UI_WORKFLOW_RULES.md)，所有 Skill 引用。
已修正联系人资料中仅见“微信号”却通过校验、微信号子串匹配及跨分区同名误选。
完整链路仍待实现，不能以 Markdown 更新或基础工具入口代替验收。

- 只读数据库解析当前账号的 username/wxid、alias 与名称历史；同名不同 ID 停止。
- 贯通通讯录→联系人候选→资料校验→聊天，支持主搜索独立弹窗、变更分区顺序、
  仅历史消息、网络建议、无结果、加载中、资料微信号缺失、备注/alias 变更。
- 群使用 @chatroom 关联，群名和私聊同名不得混选。
- 完整且不同的快照用于 missing/inferred_removed；系统信号或用户确认用于
  confirmed_removed；恢复保留历史。对方删除自己不能从本地通讯录直接推断。
- 发送入口核验 person/conversation/status，确认令牌绑定稳定收件人、正文及版本；
  修改 contact 参数、换聊天、布局变更、失联状态、身份不符都必须拒绝发送。
- 同帧输入区域定位与回复正文核对；提交后识别可观察结果，失败/拒收不标成功，
  不自动重发、不发送探测消息、不自动加好友。
- 修复旧 open_chat 搜索流程和回复 MCP 的完整目标绑定；缺少状态或 UI 身份证明
  时 fail closed。明确失败码与本机证据，不输出私人信息。

依赖：WA-001/002/003/004。完成标准：上述状态组合自动化测试通过；文件传输助手
及用户明确指定的测试联系人完成只读导航验收，发送/删好友/改资料逐次确认；
删除场景优先脱敏回放，不为验收删除真实联系人。历史归档始终保留。

### WA-001 当前帧 OpenCV 控件定位 — P0 / in_progress

旧的按微信版本/窗口尺寸加载坐标档案路线已从 0.7.0 移除，不再开发坐标校准器。

当前帧识别、幂等导航有界恢复和图片复核需覆盖以下场景：

- 不同主题/DPI/窗口大小、内部栏宽、窗口移动、辅助窗、焦点丢失和用户中断。
- 通知角标遮挡、选中/未选中图标、未知或重复候选；每步核验 HWND 与目标页面。
- 联系人更多、聊天详情、表情入口和个人相册返回等控件的当前帧检测。
- 个人相册入口、加载、退出的连续后置验证；识别与输入派发分别验收。

### WA-006 窗口、个人联系人分组与图片复核 — P0 / in_progress / 0.8.x

已实现：连接 PID 绑定、每 HWND 独立观察、分层页面唯一选择、声明路由、有界恢复、
仅关闭已知只读辅助窗；个人联系人标题/箭头/成员范围；120 秒单次图片复核计划。
下一步按顺序验收：
1. 通知角标遮挡聊天图标、浅色/DPI/内部栏宽变化、窗口移动和辅助弹窗；每步保存
   本机前后证据，未知窗/多个候选/过期图拒绝，不沿用旧框。
2. 多分组展开、联系人标题滚出/置顶、列表虚拟化、同名/无 alias/浮动资料卡。
   只认个人分组，身份不足停止，缺席不推断删除。
3. 单联系人→精确 alias→唯一个人相册→滚动加载→关闭/恢复→本地库重读。
   先一人再连续多人；空白、限时可见、无变化记 restricted/stalled/partial。
4. 自动加载队列失败交接复核计划与恢复状态；停止当前批次，复核成功也须重新核验
   联系人和相册身份，不能直接将原任务标完成或跳下一个人。
5. 再验收远程媒体清单、逐项确认、下载断点与内容哈希，保留旧归档全部正文。

完成标准：上述不同尺寸/分组/失败场景实机通过；任何辅助窗口不会被误作目标，
任何 新的朋友/历史消息/网络候选不会成为个人收件人。发送/删除等不在图片复核白名单。

0.8.1 增加显式资料字段合并、朋友圈队列自动补采、精确缓存哈希归档和单项远程下载。
仍须实测：签名分行/折叠与未显示、别名 OCR 错字不能模糊放行、源数据空值不抹去
UI签名、资料窗口移动时保存原帧证据；真正一项联网下载确认→格式校验→BLOB→回执。
基础设施实现不能替代业务端到端验收。

完成标准：目标位置来自当前帧；窗口变化后重新识别；导航后置条件与完整朋友圈
入口/加载/退出连续验收成功。语义 ID 表示用途，不携带静态坐标。

### WA-002 通用待确认动作模型 — P0 / in_progress

目标：所有外部修改统一使用持久化计划、完整负载哈希、过期时间和单次令牌。

- 已完成：回复草稿、联系人备注和删除的目标/内容绑定。
- 待完成：发送文件、图片、表情，朋友圈点赞、评论，远程媒体下载。
- 失败、过期、内容变化或令牌已用时必须重新生成计划并确认。
- 记录准备、确认、执行、失败和验证状态，不保存不必要的敏感正文。

完成标准：每种外部动作都有“篡改负载、复用令牌、过期令牌、执行失败不重试”的自动化测试。

### WA-003 真实运行时 MCP 装配 — P0 / planned

目标：提供一个明确的启动入口，把只读数据库、MemoryStore、`AgentLoop`、唯一 `BasicSkill` 和 stdio MCP 连接起来。

- 启动时输出版本兼容结果和非敏感健康状态。
- 数据库、微信窗口或布局档案缺失时，只有相关工具不可用，状态工具仍可诊断。
- 进程退出时关闭 SQLite、目录监听器和临时资源。

完成标准：冷启动、重启、微信未运行、数据库锁定和 schema 不兼容测试通过；工具清单与运行时依赖一致。

### WA-004 安全实机动作矩阵 — P0 / in_progress

目标：逐项记录“代码存在、自动化测试、真实微信验证”的差异。

覆盖搜索框→右侧内容→关闭标签保留聊天、联系人弹窗与发现内容等路径。
具体边界和未完成项见 [ACTION_VERIFICATION_MATRIX.md](ACTION_VERIFICATION_MATRIX.md)。
优先补多标签切换/关闭/返回，以及右侧公众号文章、视频号详情和小程序路径。

- 首先只使用文件传输助手验证打开会话、准备草稿和取消。
- 发送文本、文件、图片和表情分别单次确认、单次执行、结果验证。
- 联系人备注只使用专门测试联系人；删除联系人不纳入默认自动验收。
- 每项记录微信版本、布局档案、结果、失败原因和回滚方式。

完成标准：`docs/ACTION_VERIFICATION_MATRIX.md` 中每个稳定动作都有日期、环境和证据摘要；未经验证的动作不标稳定。

## 0.6.x：归档完整性和增量调度

### WA-101 来源账本与覆盖率 — P0 / planned

目标：让每条导入来源、时间范围和重叠关系可追踪。

- 为每个导出、当前 4.x 分库、官方备份和旧账号目录分配 `source_id`。
- 记录文件指纹、读取行数、新增数、重复数、失败数、最早/最晚时间和会话覆盖。
- 生成来源交集、缺口和无法证明完整的范围报告。

完成标准：所有 540,430 条现有消息都能追溯到至少一个来源账本；不能证明的范围明确标为 unknown。

### WA-102 旧版历史恢复 — P1 / blocked

依赖：用户通过微信官方“聊天记录迁移/备份与恢复”提供可由当前 4.x 读取的历史。

- 继续只读审计旧账号目录、`Msg/Multi/bak` 和官方备份。
- 不直接解密后覆盖当前目录，不移动或删除原始文件。
- 迁入后按稳定消息 ID 和内容指纹合并，并更新来源账本。

完成标准：官方迁移前后覆盖差异可复现，旧源原文件哈希不变。

### WA-103 媒体归档任务队列 — P1 / planned

目标：图片、语音、视频和文件按独立任务断点续跑。

- 任务状态包含媒体引用、内容哈希、尝试次数、错误类别、下次可运行时间和本地/远程属性。
- 本地缺失不会回滚消息正文；远程下载保持逐次确认。
- 不重复扫描已完成且输入指纹不变的媒体。

完成标准：中途终止后仅恢复未完成项；重复运行不新增 BLOB；错误报告不打印密钥或私人内容。

### WA-104 多会话目录事件调度 — P1 / planned

目标：把已验证的单会话目录监听扩展为去抖、合并和可恢复的多会话调度器。

- 文件事件只触发受影响分库和会话，不轮询全历史。
- 支持事件风暴合并、断线重连、游标回退检测和进程重启恢复。
- 同一消息只生成一次归档引用和一次分析失效传播。

完成标准：模拟事件风暴、重复通知和进程重启时，消息、任务和水位均保持幂等。

### WA-105 资料、群成员与消失对象长期快照 — P1 / planned

目标：补全本人、联系人、群成员、头像、签名、背景和群身份变化。

- 优先数据库字段；OCR 只补充当前资料页确实可见的字段。
- 一次缺失只标 `missing`；三次且跨 24 小时才可推断移除。
- 重新出现时记录恢复，不删除旧资料或分析。

完成标准：改昵称、备注、群昵称后仍关联同一 person；同名不同 wxid 永不自动合并；缺失和恢复测试覆盖完整。

## 0.7.x：语义分析生产化

### WA-201 分析 Worker 与模型适配器 — P0 / planned

目标：让外部 Agent 可持续领取、续租、失败重试和完成分析任务。

- 支持月度、会话汇总、人物、关系、事件和仪表盘任务。
- 限制单次输入页大小；默认使用紧凑上下文，证据按需展开。
- 区分可重试错误、输入缺失、父版本冲突和永久模板错误。
- 记录模型/提示模板版本、输入指纹、耗时和非敏感用量统计。

完成标准：任务崩溃可恢复；两个 Worker 不重复提交；父版本冲突不会覆盖新结果。

### WA-202 首批 281 个月度任务 — P1 / planned

目标：完成当前前五私聊和前五群聊的全部月度分析。

- 每月生成完整 Markdown、短 Claim、Event phase、覆盖水位和证据关系。
- 对开放事件跨月延续，不因月份切断。
- 抽样人工核对重要事件、承诺和说话人归属。

完成标准：281 个任务全部有成功或明确不可处理状态；随机抽样不存在证据串人、日期越界和旧结论丢失。

### WA-203 会话、人物和关系汇总 — P1 / planned

目标：月度结果完成后生成跨月会话 Memory、场景化人物 Memory 和关系时间线。

- 私聊、工作群、朋友群、家庭群和朋友圈表达分开保存。
- `self` 与联系人使用同一证据规则，但用户修正拥有最高优先级。
- 头像、签名或单条朋友圈只能作为观察，不能单独推出心理状态。

完成标准：同一人物不同场景不会被全局描述覆盖；每个重要结论可展开到证据；冲突结论保留有效期。

### WA-204 分析质量评估与回归集 — P1 / planned

目标：建立脱敏的本地评估样本和确定性结构验证。

- 评估说话人、日期、承诺状态、事件连续性、场景归属和证据充分性。
- 模板或模型版本升级前运行回归比较。
- 不把真实聊天内容提交 Git；测试数据使用合成样本。

完成标准：关键结构指标有阈值；版本升级产生可审查差异报告。

### WA-205 用户修正闭环 — P1 / planned

目标：用户可确认、否定、改写和限定结论。

- 修正生成 append-only 记录并使依赖节点失效。
- 重新分析时优先使用有效修正，历史推断保留为 superseded。
- 支持身份合并后的拆分重建。

完成标准：修正后不会在下一次增量分析中被旧推断覆盖；可追踪修正影响的版本范围。

## 0.8.x：稳定 UI 业务动作

### WA-301 消息目标定位和管理 — P1 / planned

目标：为单条可见消息建立语义目标，支持复制、引用、转发、撤回、删除和多选。

- 目标绑定会话、稳定消息 ID、时间、方向和局部内容指纹。
- OCR/CV 只验证可见气泡位置，不以屏幕第 N 条作为长期身份。
- 撤回、删除、转发属于外部修改，逐次确认。

完成标准：列表滚动或插入新消息后不会命中错误气泡；歧义时停止。

### WA-302 引用回复与群艾特实机闭环 — P1 / planned

- 引用菜单必须唯一定位，并在编辑区验证引用卡片。
- 群艾特必须验证微信内部艾特标签，而非仅验证输入了 `@名字` 文本。
- 发送继续走草稿、确认、发送回执和结果验证。

完成标准：测试群和文件传输助手场景的成功、取消、歧义和失效布局均有记录。

### WA-303 联系人备注与删除验收 — P1 / blocked

依赖：WA-001 的对应语义坐标以及专用测试联系人。

- 备注修改后重新读取 `contact.db`，验证同一 wxid 的 remark 变化并生成资料快照。
- 删除动作默认不自动测试；执行时确认界面显示、wxid、计划内容和删除后同步结果。
- 删除失败或对象仍存在时不得写 `confirmed_removed`。

完成标准：备注端到端闭环通过；删除只在用户明确安排的测试对象上形成独立验收记录。

### WA-304 朋友圈读取与动作 — P2 / in_progress

- 0.6.0 已实现双路径覆盖账本、逐人限页队列、退出/中断恢复、方向明确的联系人
  删除/拉黑状态工具，见 CONTACT_COLLECTION.md；本地路径要求重复归档幂等。
- UI 入口需按当前帧验证：
  补齐个人相册实际截图、精确身份入口、不同窗口形态、返回/关闭与受限提示样本。
- 好友/拉黑字段必须按微信版本验证含义；当前只接收用户或人工核对系统信号，
  不用 local_type、搜索失败、空相册推断对方删除/拉黑。
- 完成标准额外要求：连续两位不同人物加载/退出不串窗，崩溃后旧 coverage/Memory
  可读，未访问对象显示缓存覆盖未知，任何路径都不宣称服务器历史完整。

- 本地刷新读取完整缓存，不凭未经验证的 local_type 丢弃其他身份条目；
  媒体计划与逐项下载规则见 MOMENTS_ARCHIVE.md。批量流程需单独端到端验收。
- 空/部分下载结果应报明确状态，远程链接、访问限制与媒体格式异常不得伪报成功。
- 批量归档先按指定稳定用户和时间范围生成清单，范围仅为当前账号可读取记录，
  不保证覆盖对方完整历史或不可见动态。每个媒体计划保留来源、权限、状态、
  哈希与确认记录；不自动扩大到其他联系人、不失败重试或跳过确认。
- 下载验证须包含文件格式/尺寸或时长，不能用路径存在证明成功；下载异常不得
  吞掉，公开错误只输出类型与状态码，私人 URL 和签名只保留本机。
- 稳定的按用户分页、单条动态定位、增量归档和本地媒体关联。
- 点赞、取消点赞、评论和发布分别建模并逐次确认。
- 操作后通过重新读取或页面状态验证结果。

完成标准：重复同步幂等；动作失败不自动重试；远程媒体未经确认不下载。

## 0.9.x：内容类型、回复策略和产品能力

### WA-401 消息类型统一 — P2 / planned

统一文本、图片、表情、语音、视频、文件、位置、名片、链接、小程序和引用消息的读取模型。每种类型定义原始引用、可检索摘要、媒体状态和回复可用性。

完成标准：未知类型保留原始元数据且不会导致整批同步失败。

### WA-402 公众号与视频号信息处理 — P2 / planned

优先使用本地数据库或非视觉接口完成文章/内容索引、作者、主题、摘要和授权 Memory 关联。OCR 不作为正文采集主路径。

完成标准：来源、发布时间、正文可用性和版权受限内容均明确；不绕过登录或访问权限。

### WA-403 自动回复策略层 — P1 / planned

目标：基于当前消息、会话 Memory、未完成事项、近期事件、对方 Claim 和本人场景表达生成草稿。

- 定义联系人/群白名单、静默时段、最大频率、敏感话题和升级人工处理规则。
- 默认只生成草稿；每次发送继续要求单次确认。
- “全自动发送”只有在未来单独设计权限模型、撤销机制和实机安全评估后才讨论，不是当前承诺。

完成标准：无关人物和月份不进入上下文；草稿可解释使用了哪些短 Claim；过期 Memory 有明确降级。

### WA-404 高层分析模板 — P3 / planned

包括相亲/关系评估、目标追踪、成长变化和自我复盘。模板必须显示证据覆盖、场景差异、不确定性和用户修正，禁止心理疾病诊断或把 MBTI 当作事实。

完成标准：模板仅消费统一 Memory，不建立第二套人物画像数据库。

## 1.0 发布门槛

以下条件全部满足后才能发布 1.0：

1. 支持的微信版本、主题、DPI 和当前帧检测器有明确兼容矩阵。
2. 数据库迁移、备份、恢复和损坏检测有自动化测试。
3. 全量归档和百万消息级增量性能完成基准验证。
4. 所有外部修改动作统一进入持久计划和单次确认体系。
5. Memory 的版本、回滚、证据展开和用户修正完成端到端验收。
6. 安装、升级、卸载和私人数据清理流程有文档。
7. 默认日志经过隐私审计，不含消息正文、身份信息、媒体或密钥。

## 明确不做

- 不注入、Hook 或修改微信进程内存。
- 不写微信数据库，不构造或模拟微信私有协议。
- 不恢复 UIA/pywinauto 控件树作为动作通道。
- 不使用物理鼠标、物理键盘作为隐藏降级路径。
- 不自动合并同名联系人，不以昵称、备注或公开微信号作为人物主键。
- 不未经确认发送、删除联系人、修改资料、点赞、评论或联网下载媒体。

## 版本变更规则

- `0.7.x`：当前帧 CV/OCR 定位、HWND 派发和动作验证；不恢复固定坐标路线。
- `0.6.x`：归档 schema、来源账本和增量调度能力。
- `0.7.x`：分析 Worker、模板和质量评估。
- `0.8.x`：通过实机验收的业务动作。
- `0.9.x`：消息类型、内容处理和回复策略。
- `1.0.0`：达到上述发布门槛。

Memory schema、MCP protocol、联系人动作 protocol 和分析 template version 独立演进。任何不兼容变更必须提供迁移或明确停止，不能静默解释旧数据。
