# 数据新鲜度与 Skill 联动规则

规则版本：1。适用于仓库内全部 WeChat Skills；本文是操作约定，不代表运行时已经
实现统一自动门禁。每个 SKILL.md 仍须写明自己的前置条件与交接对象。

## 任务范围与新鲜度

先确定稳定 person_id/conversation_id、时间范围、任务用途，以及以下模式之一：

| 模式 | 前置条件 | 输出含义 |
|---|---|---|
| 历史快照分析 | 固定证据范围、来源和版本，说明缺口 | 截至该快照的分析，无须为了过去月份加载所有最新 UI |
| 当前状态分析 | 更新相关来源，索引增量，处理受影响的上游分析 | 截至本次成功同步/观察的状态 |
| 回复草稿 | 当前会话最新消息、对象状态、相关 Memory 与未完成事项检查 | 基于指定新消息的草稿，不授权发送 |
| UI 操作 | 当前 HWND、页面、同帧控件与身份核验 | 当前页面的一步操作，旧截图不是有效输入 |

区分来源新鲜度、归档新鲜度、分析新鲜度和 UI 帧新鲜度。文件修改时间、数据库
能打开、任务计数为零、current.md 存在或 OCR 成功，都不能单独证明数据是最新的。

一次成功同步只证明其实际来源范围：本地朋友圈 cached_only 不证明服务器完整
历史；部分相册加载不证明所有动态可见；资料未显示字段不证明字段为空。
没有可核对的水位/覆盖/版本信息就标 unknown，不自行编造 checked_at 或消息水位。

## 现有接口的职责

| 操作 | 实际职责 | 不代表什么 |
|---|---|---|
| status.summary | 应用/协议版本、计数与有限 pending 任务列表 | 不是所有来源新鲜度或完整 dirty/failed/running 状态 |
| monitor.run_once | 指定会话的一次增量读取；配置归档时同步归档，返回水位/消息/上下文 | 不同步所有会话或朋友圈，也不自动完成分析任务 |
| sync.contacts_moments_local | 更新本地可读联系人资料与朋友圈归档、索引 | 不读取远程完整历史、不下载媒体、不认证当前好友关系 |
| sync.index_archives | 索引项目已经存在的归档 | 不从微信采集最新消息，不能替代上一层同步 |
| sync.capture_contact_profile | 唯一且身份核验的资料页显式字段补采与索引 | 不猜测隐藏签名或身份 |
| sync.load_contact_moments | 逐人有界 UI 加载后重新读取本地库 | 不证明远程完整覆盖、不授权媒体下载 |
| sync.moments_coverage | 读取目标人物的缓存/UI 覆盖记录 | 不是好友删除证明 |
| analysis.jobs / analysis.claim_job | 有限 pending 列表 / 原子领取下一任务 | 列表空不代表依赖就绪；领取不能按任意指定范围过滤 |
| analysis.get_*_input | 读取当前归档或已存在 Memory 作为分析输入 | 不自动执行同步或外部 Agent 分析 |
| analysis.submit | 提交完整 Markdown、短 Claim/Event 与覆盖；后端计算输入指纹 | 不接受客户端伪造的指纹或自动补齐未完成上游 |
| charts.refresh | 根据已有结构化结果生成视图 | 不更新来源或完成分析 |

工具可能因 history_db、profiles_db、moments_db 或 UI/backend 未装配而不可用。
先检查可调用工具，不调用不存在的 sync.ensure_current、analysis.coverage 等接口。
完整消息归档用现有只读后端/归档入口；monitor.run_once 不是完整历史导入替代品。

## 按依赖顺序联动

```text
当前状态请求
  → wechat-sync：来源 → 原始归档 → Memory 索引
  → wechat-identity-audit：需要时解决身份/状态歧义
  → wechat-monthly-analysis：只更新受影响月份
  → wechat-conversation-summary：合并成功月份
  → wechat-person-analysis：相关会话 + 资料 + 朋友圈，保留场景差异
  → wechat-timeline：整理连续事件及实际依赖
  → wechat-dashboard：展示已成功提交的结构化结果

资料/朋友圈新增
  → wechat-profile-moments → wechat-sync 索引
  → 相关人物/事件/会话增量分析 → 时间线/仪表盘

新消息回复
  → wechat-reply-monitor → wechat-sync / 身份核验（需要时）
  → 更新与回复相关的受影响分析（需要时）
  → 重新构造紧凑上下文 → 草稿 → 用户确认 → BasicSkill → 验证
```

Skill 联动表示当前 Agent 读取相关 SKILL.md 并使用其流程/MCP 工具，不是把
Skill 名当成可调用函数；也不自动创建代理、后台任务或跨会话发送消息。
只执行完成当前任务所需的节点，不全量重分析所有人、加载所有相册或展开全部证据。
图片复核、身份修正、媒体下载和发送继续遵守各自授权边界，授权不沿联动链扩大。

## 交接与停止

每次交接提供简短的任务上下文：稳定范围、来源/实际覆盖、水位或输入版本、
成功提交的输出版本、已知缺口、需更新的下游节点。复用 MCP 回执和数据库版本，
不创建一套重复 YAML/JSON 记忆文件，也不把原始聊天全文传给每个下游 Skill。

上游未成功、输入分页未读完、身份不明或当前请求无法证明来源已更新时，停止把
下游结果称为当前。历史分析可保留最后成功版本并标明截至范围；当前回复不在
新消息读取失败时继续，缺少身份/页面证明不能发送。

已有旧 Memory 但相关分析滞后时，草稿必须标明滞后并避免依赖未经更新的承诺、
关系或状态结论；需要这些事实才能正确回复时先完成相关分析，否则停止草稿。
确认前重新读取目标会话；新消息、状态、正文或相关上下文变化影响草稿时，重新
生成草稿并取得新确认。不能声称现有确认令牌自动完成这些数据检查。

按父版本、证据输入和受影响范围去重；没有新输入不创建新版本或反复联动。
事件更新反向影响会话/人物时，只处理真正变化的依赖，不能形成无限刷新循环。
领取任务后核对返回的 scope_type/scope_id/period，不把别的范围任务当作当前任务
提交或完成；指定范围领取不支持时交给调度器处理，明确接口缺口。

## 运行时边界

目前有水位、版本、覆盖与任务基础设施，但 MCP 没有统一的按范围新鲜度查询和
强制联动门禁，也没有完整依赖就绪查询。无法通过现有回执证明的部分必须保留
unknown。后续运行时工作见 FUTURE_TODO.md 的 WA-007，不能用本文代替实现。
