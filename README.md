# 🎯 一站式全自动化微信 AI Agent 综合系统：双层闭环框架与系统规格说明书（最终完整版）

---

## 一、 系统架构设计与双层决策引擎

本系统旨在构建一个基于 Windows 桌面端微信的**无人值守全自动化 AI Agent 综合代理系统**。系统抛弃传统的 OCR（图像识别）方案，采用原生的 **UIA（UI Automation）控件树解析**，将微信界面的所有交互解耦并封装为“双层动作空间”，结合大模型（LLM）实现自我感知、自动决策、精准执行与状态归位闭环。

```
                        ┌─────────────────────────────────────────────────────────┐
                        │              1. AI 决策与事件调度引擎 (Brain)             │
                        │    (未读感知 ➔ 策略路由 ➔ 动作执行 ➔ 校验与自愈归位)    │
                        └────────────────────────────┬────────────────────────────┘
                                                     │
                                 ┌───────────────────┴───────────────────┐
                                 ▼                                       ▼
                     【第一层：高层常用复合功能包】          【第二层：原生 UI 原子组件字典】
                       (Tier 1: 高效快捷技能包)                 (Tier 2: UIA 控件树)
                     ────────────────────────                ────────────────────────
                     • 覆盖 90% 日常自动化需求               • 覆盖 10% 复杂/未知兜底需求
                     • 1 步到位、高速度、低 Token            • 精准控件定位、原子级交互
                                 │                                       │
                                 └───────────────────┬───────────────────┘
                                                     ▼
                        ┌─────────────────────────────────────────────────────────┐
                        │                 2. 微信桌面端 UI 交互界面               │
                        └─────────────────────────────────────────────────────────┘
```

## 二、 第一层：高层常用复合功能包（Tier 1: 快捷技能包 - 90% 场景）

该层将复杂的界面交互在后台打包为单一技能，AI 仅需传入参数即可完成全套操作，无需处理中间界面逻辑。

### 2.1 消息感知与未读提醒
* **`检查未读消息队列`** (`get_unread_messages`)：
  * **功能**：自动扫描侧边栏及会话列表中带红点或 `[N条未读]` 标记的会话。
  * **返回数据**：`[ {联系人: "张三", 未读数: 3, 最新消息预览: "开会资料收到了吗？"} ]`

### 2.2 精准搜索与环境归位
* **`精准打开联系人聊天`** (`open_contact_chat`)：
  * **核心规范**：强制先切换到“通讯录”专属搜索框进行搜索匹配，严禁使用全局主搜索框混淆联系人与公众号。
  * **参数**：`目标名字`
  * **逻辑**：点击通讯录Tab ➔ 输入搜索 ➔ 点击匹配项 ➔ 自动按 Esc 清空搜索状态。
* **`重置并清理 UI 环境`** (`reset_ui_environment`)：
  * **功能**：强制关闭所有弹出的独立窗口（朋友圈 `SNSWnd`、搜一搜 `TopStoryWnd`、聊天记录查找窗口），清空搜索框文本，切回主消息 Tab，恢复系统空闲状态。

### 2.3 消息收发与多媒体投递
* **`发送文本消息`** (`send_text_message`)：直接向目标联系人/群组发送文本。
* **`发送引用回复消息`** (`send_quoted_message`)：在目标聊天框中搜索特定历史关键词气泡，右键“引用”并写入回复内容。
* **`群聊 @ 成员回复`** (`send_group_at_message`)：在指定群聊中 @ 某人或所有人并发送消息。
* **`发送图片/剪贴板表情包`** (`send_image_or_sticker`)：读取本地图片/表情包文件至剪贴板，聚焦输入框执行快捷粘贴发送。
* **`发送文档文件`** (`send_file`)：向目标发送本地文件（PDF、Word、ZIP 等）。
* **`发送微信内置/自定义表情`** (`send_builtin_sticker`)：
  * **参数**：`目标名字`、`表情分类`（默认黄脸/收藏表情）、`表情序号/名称`
  * **逻辑**：打开聊天框 ➔ 点击工具栏表情按钮 ➔ 切换对应 Tab ➔ 点击指定表情发送 ➔ 自动关闭表情面板。

### 2.4 聊天记录检索与提取
* **`提取聊天历史记录`** (`get_chat_history`)：
  * **参数**：`目标名字`、`提取条数 (limit)`、`起始时间`、`结束时间`、`搜索关键词`
  * **逻辑**：支持直接从主聊天框滚动提取最近 N 条，或自动打开“查找聊天记录”独立窗口按时间段/关键词精准筛选导出。

### 2.5 朋友圈全场景自动化
* **`获取特定好友朋友圈`** (`get_friend_moments`)：
  * **参数**：`好友昵称/备注`、`limit (最近 N 条)`
  * **状态返回值**：
    1. `SUCCESS`：获取成功，返回动态列表（正文、图片、时间、点赞评论）。
    2. `EMPTY`：**该好友朋友圈无内容/仅展示近期**。
    3. `NO_ACCESS`：**已被对方屏蔽/非好友/已拉黑**。
* **`获取朋友圈大厅时间线`** (`get_my_timeline`)：
  * **参数**：`limit (最近 N 条)`、`hours_range (最近 X 小时内)`
  * **返回**：朋友们最新发出的动态流列表。
* **`获取自己朋友圈历史`** (`get_my_own_moments`)：
  * **参数**：`limit (最近 N 条)`
  * **返回**：自己过去发布过的历史朋友圈动态。
* **`朋友圈互动与发布`**：
  * **`朋友圈点赞`** (`like_moment`)：对指定好友的动态点击“赞”。
  * **`朋友圈评论`** (`comment_moment`)：自动对指定动态发表 AI 评语。
  * **`发布朋友圈`** (`publish_moment`)：自动填充图文并发布新的动态。

### 2.6 公众号与视频号服务
* **`搜索并下载视频号视频`** (`download_channels_video`)：在视频号窗口中检索指定关键词，定位视频并自动下载至本地。
* **`检索公众号文章`** (`search_official_article`)：检索特定公众号文章并提取正文与链接。

## 四、 第二层配套：原子组件操作工具集 (Atomic UI Tools)

AI 降级使用第二层组件时，由后台提供的 **7 个原子控制工具**：

1. **`get_ui_tree(window_title)`**：提取指定窗口的 UIA 控件树，返回包含控件 ID、类型、名字的结构化 JSON。
2. **`click(component_id)`**：根据控件 ID 触发物理点击或 UIA Invoke 动作。
3. **`input_text(component_id, text)`**：向指定输入框组件写入字符。
4. **`right_click(component_id)`**：右键点击控件（用于弹出消息右键菜单）。
5. **`scroll(component_id, direction, distance)`**：向上/向下滚动列表或朋友圈流。
6. **`send_keyboard_shortcut(key_shortcut)`**：发送按键组合（如 `'^v'` 粘贴、`'{ENTER}'` 提交、`'{ESC}'` 退出）。
7. **`close_window(window_id)`**：强行关闭特定子窗口。

## 五、 系统闭环运行与环境自愈规范 (Closed-Loop Workflow)

```
       ┌────────────────────────────────────────────────────────┐
       │ Step 1. 感知 (Perceive)                                │
       │ 轮询调用 `get_unread_messages()` 扫描红点与未读消息    │
       └───────────────────────────┬────────────────────────────┘
                                   │
                                   ▼
       ┌────────────────────────────────────────────────────────┐
       │ Step 2. 决策与路由 (Decide & Route)                    │
       │ AI 判断意图，**优先选择【第一层快捷技能包】**          │
       │ (例：收到消息 ➔ 调用 `send_text_message`)              │
       └───────────────────────────┬────────────────────────────┘
                                   │
                    ┌──────────────┴──────────────┐
              技能正常运行                   遇异常/未知界面
                    │                             │
                    ▼                             ▼
       ┌────────────────────────┐    ┌─────────────────────────┐
       │ Step 3A. 执行高层技能  │    │ Step 3B. 降级原子组件   │
       │ 自动完成找人、输入、  │    │ 获取 `get_ui_tree()`,   │
       │ 发送全套流程           │    │ AI 一步步点击控件处理   │
       └────────────┬───────────┘    └────────────┬────────────┘
                    │                             │
                    └──────────────┬──────────────┘
                                   │
                                   ▼
       ┌────────────────────────────────────────────────────────┐
       │ Step 4. 自愈与复位闭环 (Validate & Reset)              │
       │ 自动调用 `reset_ui_environment()` 关闭所有弹窗与搜索框 │
       │ 强制将微信界面恢复至主消息列表空闲状态，等待下一次循环 │
       └───────────────────────────┬────────────────────────────┘
                                   │
                                   └───────(返回 Step 1 循环)
```

### 闭环三大核心保障原则：
1. **防混淆导航**：查好友/群时强制在通讯录中操作，搜文章/视频时在全局框操作。
2. **状态强制归位**：无论任何任务执行成功或中途报错，Step 4 必须触发环境复位，关闭所有子窗口（朋友圈 `SNSWnd`、搜一搜 `TopStoryWnd`、表情面板），按 `Esc` 清空搜索残留。
3. **分级降级机制**：90% 的通用任务通过 Tier 1 快捷技能瞬间完成（省 Token、高稳定性）；10% 的边缘场景依靠 Tier 2 控件字典兜底，确保系统**绝不挂起、永远自我复位**。
