# UI 问题与处理方案

用于定向发送、窗口导航、资料/朋友圈采集的排错与实测规划。
本文保存可复用的处理规则，不保存账号、正文、截图、运行次数或发送流水。
实际验收范围和证据仍记录在本机忽略的状态/问题/解决台账中。

## 先区分任务

- 指定一个联系人发送：直接搜索目标，识别结果分区，选择完整名称精确唯一的联系人，核验资料 alias，再回到同一聊天。
  搜索词可为前缀；查询词与候选完整名称分别核对。不得因完整名称进入“最常使用”分区就选择它替代联系人分区。
- 连续采集联系人资料与个人朋友圈：确认个人“联系人”分组展开，再在该分组下逐人定位。
  不将定向发送改成滚动遍历，也不将采集失败自动降级为混合搜索。
- 用户要求测试 OpenCV + OCR 全流程时，正常步骤仅使用识别器返回的当前帧证据。
  失败后才查看图片排错；Agent 看图或复核导航成功不能算自动检测器验收通过。
  其他任务按用户指定的复核方式处理。

## 问题与解决方式

“已实现”仅表示当前代码有对应处理，不表示所有微信版本、主题、DPI、窗口形态或 MCP 入口均已验收。

| 问题 | 原因或判断依据 | 处理方案 | 实现边界 |
|---|---|---|---|
| 最小化主窗被独立相册替代 | 同 Qt 类名且按面积选窗会误绑 | 用当前 Win32 主框架样式区分顶层窗口；多个候选停止 | 已实现；不按标题、面积或历史 HWND 取窗 |
| 未选聊天时主页面 unknown | 没有聊天正文和发送按钮，文字规则不足 | 同时核对选中的聊天导航图标、公共空状态标志及无输入区/竞争页面 | 已实现；单个图标不证明页面 |
| 滚动个人相册失去标题 | 相册只剩年份、日期列和范围页脚 | 组合年份、日历结构和明确可见范围页脚；排除聊天输入区及竞争页面 | 已实现；相册页面不证明人物身份或采集完整 |
| 侧栏图标互相误匹配 | 聊天气泡、发现等轮廓有弱交叉匹配 | 多尺度匹配要求高分且领先其他空间峰；重复、缺失或近似候选拒绝 | 已实现；跨运行的导航后置失败仍需新证据定位，不能统归这一原因 |
| 主窗截图缺少独立搜索内容 | PrintWindow 不包含另一个 Qt popup | 主搜索字段用前台可见帧核对；各辅助 HWND 单独截图、OCR 与页面观察 | 已实现；合成可见图不能把 popup 内容认证为主聊天 |
| 搜索重入拼接旧词或选错分区 | 输入前未清场；结果分区随查询/状态变化 | 仅关闭已识别的关联搜索弹窗，清空并 OCR 核对字段；重新观察分区，拒绝历史、群、网络及“最常使用”替代 | 已实现基础路径；资料采集不使用搜索兜底 |
| 网络查询回显不可见 | 联系人结果较多，网络建议位于可见范围外 | 选择前直接重新 OCR 核对主搜索框；可见网络首项仅作回显证据，不点击 | 已实现；不要求为了查询证明滚动到网络结果 |
| 小字号姓名 OCR 为异体或近似字 | 同帧局部放大能恢复精确识别 | 对当前动态区域放大 OCR，再把框坐标除以放大倍数并加区域原点 | 已实现；不做姓名/alias 模糊放行，仍不一致就停止 |
| 点聊天标题未打开资料卡 | 标题实际切换聊天信息侧栏 | 用侧栏独立文字锚点、精确成员名和当前头像轮廓定位资料入口；核对 alias 后关闭资料卡和侧栏 | 已实现定向私聊路径；群资料另行处理 |
| 资料卡或表情弹窗 owner=0 被拒绝 | 同进程 Qt 辅助窗不总设置 owner | 对资料/表情核对唯一同进程、窗口类型、明确页面及具体后置条件；资料继续核验 alias | 已实现限定路径；搜索 popup 仍要求 owner 对应主 HWND，不能统一放宽 |
| 关闭辅助资料卡被误判为关闭主窗 | 辅助绑定的 handle 被当作调用方主窗口 | 从主 BasicSkill 指定辅助 HWND 执行已登记关闭，再验证辅助窗消失 | 当前路径已修正；辅助绑定的全局角色语义仍须复核，主窗关闭保护不解除 |
| 输入区工具图标被 OCR 成既有正文 | 工具行图标可能读作数字或字母 | 以当前发送按钮所在动作行分隔正文区，排除动作行；正文区真实字符仍算草稿 | 已实现；真实数字草稿不能当图标丢弃 |
| 消息发出后错误返回 unknown | 左侧其他会话的同文预览参与新增计数 | 前后计数仅限同一聊天右侧消息区；结合确切正文 OCR、当前绿色气泡和正文清空验证 | 已修正计数；结果观察不是服务端送达证明 |
| 原生表情面板打开但页面未识别 | 面板目录存在，运行时仍缺公共图标/标签组合 | 当前输入区匹配公共笑脸；弹窗核对默认标签与收藏心形，或收藏心形的选中背板 | 已实现入口、收藏标签和只读关闭；不证明任一格素材身份 |
| Memory 表情无法对应当前格 | 历史 md5/hint 有记录，但缓存加密、素材不可解码或当前格无精确对应证据 | 保留历史候选；补素材解码/精确资产匹配/当前格与结果验证 | 待实现；文字含义、使用次数或旧坐标不能单独证明同一素材 |
| 改完检测器仍执行旧实现 | 运行进程已缓存旧 Python 模块 | 验收前确认实际 runtime 已载入新实现；按当前工具支持的方式重启/重新装配 | 修改源码/Skill 不表示在运行的 MCP 或测试会话已更新 |

## 失败后如何继续

1. 保存第一次动作回执，并区分没有派发、已经提交、结果观察不足。
2. 新观察需重新绑定 HWND、PID、几何、DPI、页面、输入区域与目标。依赖旧帧的坐标和 review 失效。
3. 无输入派发的定位失败可以修检测器后重新准备。仅已登记的幂等侧栏导航允许有界恢复；菜单、关闭和发送不自动重复。
4. 已提交的发送返回 unknown 时，保留原回执；可增加只读结果证据，不自动重发。
   用户确实要求重发时，需要针对新的单次动作确认，并重新核验身份和正文。
5. 图片排错发现定位错误后，修正检测器并用新帧重跑。发送、表情、删除或下载不得由图片复核坐标执行。
6. 本地素材解码失败时，不用临时文字、静态图片或文件替代原生表情；联网下载仍是独立确认动作。

## 当前接口与停止条件

下列是 Python `BasicSkill` 方法，不是自动存在的 MCP 工具名：

- `prepare_search(query)`：核对当前搜索输入，不代表已经选中联系人。
- `select_search_result(query, section, username, result_name)`：区分查询与完整候选名；私聊选择后仍待 alias 核验。
- `verify_searched_contact_alias(expected_alias)`：资料 alias 精确比对，并验证回到同一聊天。
- `close_private_chat_details(query)`：仅关闭明确识别的私聊信息侧栏，不修改设置。
- `send_current_verified_text(text, confirm=True)`：要求已验证的收件人、确切正文和空草稿；提交后观察可见结果。
- `open_emoji()`、`open_emoji_favorites()`：只打开面板/收藏标签，不发送。
- 关闭资料或表情辅助窗：从主 BasicSkill 调用 `page_operation('close', hwnd=当前辅助HWND, expected_page=明确页面)`。
- `send_sticker(cell)` 与旧目录坐标发送不提供可靠素材链路，已拒绝原始格坐标。不能把它们当成可用发送能力。

页面未知、分区错误、同名歧义、alias 缺失/不符、当前窗变化、既有草稿、正文不符或素材不可核对时停止相应动作。
基础接口局部可用不能替代 WA-005 的完整身份/状态/确认链路，也不能代替 WA-007 的运行时依赖门禁。

## 下一阶段的表情方案

按依赖顺序推进，不因入口实测通过就标记发送完成：

1. 只读确定历史素材的稳定 md5、原始引用、格式与解码来源；密钥使用本机 DPAPI，不打印或上传。
2. 取得可解码素材后，依存储契约写入项目自己的 `message_media` BLOB；保留素材 hash、来源和不可用状态。
3. 用当前表情弹窗的新帧匹配素材与唯一格；多候选、遮挡、未加载或无匹配停止，废弃旧尺寸/行列坐标。
4. 在 BasicSkill 增加素材绑定的单次发送入口，提交前重新核验当前收件人、素材、窗口与确认。
5. 提交一次后独立核验新增原生表情消息、面板/输入状态和失败信号；结果不足保持 unknown，不重复点击。
6. 先做脱敏回归和只读匹配，再对文件传输助手及用户指定联系人逐项实际验收。运行结果仅写本机台账。
