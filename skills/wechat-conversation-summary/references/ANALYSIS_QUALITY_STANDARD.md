# 人物、会话与月度分析质量标准

执行前核对 [分析存储与来源契约](MEMORY_STORAGE_CONTRACT.md)，固定数据库、正文根目录与来源清单。

语义模板版本：`analysis-quality-v7`。供月度、会话、人物、时间线和重建 Skill 共用。
这是 Agent 的执行与验收约定；现有 MCP 不自动验证语义阅读量、维度完整度或日期结论。

## 0. 两条分析流程与依赖

通用分析分为会话分析和人物分析，不能套用同一份画像模板。支持普通朋友、
同事、客户、家人、陌生联系人和各种群聊；恋爱只在有证据或用户确认时启用。
场景可以混合或随时间改变，不凭备注、称呼或群名确定关系。

| 流程 | 会话分析 | 人物分析 |
|---|---|---|
| 主键/范围 | conversation_id + 月份，再跨月汇总 | person_id + 已授权的相关来源 |
| 目的 | 知道这个对话里发生什么、怎样沟通、还有什么待办 | 知道这个人在不同场景的特点、偏好与变化 |
| 主要输入 | 当前私聊/群的消息、成员身份、相关已核验资料 | 成功的私聊与共同群聊分析 + 资料历史 + 朋友圈 + 用户修正 |
| 粒度 | 细到具体事项、请求、任务、决定、话题片段与互动 | 聚合去重，保留场景差异、重复模式及时间演化 |
| 重点 | 事情/话题/协作、双方或群成员的本场景聊天习惯、角色和边界 | 个人事实、兴趣喜恶、性格表现、价值观、情绪、生活/职业、跨场景行为 |
| 输出 | 完整月度与会话 Memory；场景 Claim、事件、待办、聊天风格 | 完整人物 Memory；个人 Claim、场景画像、变化时间线 |
| 下游 | 回复上下文、人物分析、会话事件图 | 人物时间线/仪表盘、相关人物的紧凑回复背景 |

```text
私聊消息 → 私聊月度分析 → 私聊长期会话 Memory ─────┐
共同群消息 + 成员身份 → 群月度分析 → 群会话 Memory ├→ 人物分析 → 人物变化时间线
个人资料快照/变化 + 朋友圈正文/本地媒体观察 ───────┤
用户描述与修正 ─────────────────────────────────┘
```

会话分析可以独立完成，不等待完整朋友圈或全局人物画像；回复优先取当前会话
风格及事项，需要时再取人物背景。人物分析依赖请求范围内实际使用的成功会话
版本，不能反过来拿旧人物画像证明会话结论，避免循环。缺某路来源时说明覆盖，
仍可生成来源受限的人物分析，但不能称为完整跨场景画像。

### 共同群聊的身份与粒度

- 按稳定成员 username/wxid→person_id 关联，群昵称只作该群展示历史。
  同名不合并；第三人转述不算目标本人说话；退出群保留成员有效时间。
- 会话层记录群用途、话题/项目、协作规则、参与角色、任务及互动；针对目标
  提取发言、主动议题、回答/求助、组织协调、分歧处理和不同成员间的互动。
  self 在该群的说话习惯也单独提取，不能套用私聊语气。
- 人物层同时比较目标与本人互动、与其他成员互动、群整体角色。同一人在工作
  群简洁正式、朋友群幽默、私聊详尽可同时成立，不能平均成一个性格标签。
- 在群里不发言只证明该范围内缺少可见发言，不能判为冷漠、不合群或没能力。
  他人评价保留评价者与语境，不自动当成目标事实；评价对象不明就不关联。
- 同一内容转发到多个群、同一事件跨私聊/群复述要按来源去重，不能算多份
  独立性格证据。群级事件仅将有实际证据的角色或行为归给个人，不能归给全员。

群消息变化先更新所属群月份和群汇总，再更新有新增行为证据、被明确提及或
角色变化的相关人物；不机械重建所有成员。群昵称/成员映射修正则回查受影响
历史月份。只使用用户授权范围内本地可读群消息，不扩大到无关群或远程采集。

## 1. 全历史分析必须有足够的月度输入

“全历史”固定为用户指定对象的实际可用历史范围，不能默认缩成最新月份。
先核对每月起止日期、消息数、媒体类型、源覆盖、双方身份和发送方向。
恢复来源的 sender 数字或显示名不可靠时，对照原始分片身份映射；无法确定作者的
内容保留为未归属证据，不加入某个人的独立画像。

把三个覆盖量分开记录，不能互相替代：

| 覆盖 | 实际含义 |
|---|---|
| 归档/读取覆盖 | 读取或索引了多少条记录、哪些分页、水位到哪里 |
| 语义阅读覆盖 | Agent 实际阅读并理解的文本时间段、消息范围与上下文 |
| 媒体内容覆盖 | 已转写/查看的语音、图片、视频；未解读内容及其可能影响 |

完整月度分析要按时间顺序分成适合上下文的块，逐块阅读全部可用语义文本，记录
块的首尾稳定消息引用与完成情况。分页过大时继续拆块；会话连续短句、引用回复
和跨块未完话题要连起来读。每块积累紧凑笔记，最后合并并回查原文，不能只把
23万条加载进脚本、统计关键词，再挑几个最长片段交给模型。

关键词检索用于发现遗漏、核实日期和回查反证，不替代按序语义阅读。不按每类
“最长3条”、每月固定几个窗口或固定几个 Claim 截断。需要输出的独立事实、偏好、
模式和变化由证据决定：合并同义冗余，保留不同对象、有效时间和场景的区别。
已索引但未语义阅读的块必须标“未分析”；不以“证据不足”隐藏没有查过。

内容解析不能只留下卡片标题就宣称读完卡片：正文、引用、转发、系统提示分别
识别来源。无法解析的内容与未转写语音作为缺口。若关键结论依赖这些内容，继续
补齐授权范围内的本地读取，或保留候选结论并说明具体缺口。

## 2. 会话层：每月的事情、话题与场景习惯

事件详述与跨时间衔接必须读取 [EVENT_ANALYSIS_STANDARD.md](EVENT_ANALYSIS_STANDARD.md)。
对重要事件还原背景、各方诉求、阶段行动、决定/变更、结果及开放事项；不以标题、
月份或几个日期替代详细过程。跨月汇总核对后续落实，区分同一事件、重复事件和话题。

月度 Memory 在一个完整 `current.md` 中检查以下维度。私聊分别记录 self 和对方；
群聊记录群整体及证据相关成员。性格/偏好只记录该会话中体现的事实或候选，
跨来源全局综合留给人物 Skill。不是每个维度都必须制造结论。

| 维度 | 应提取的具体内容 |
|---|---|
| 事情与任务 | 起因、参与人、时间、请求/约定/决定、负责人、期限、完成/取消证据、开放问题 |
| 话题与知识 | 经常谈什么、谁发起、怎样延续/转移、信息/经验/观点与讨论结果；区分事实和观点 |
| 人物事实与日期 | 本场景出现的身份、生日、经历和关键节点；入职、交付、合作、考试等具体日期 |
| 兴趣、喜好与厌恶 | 食物口味、娱乐/作品/人物、活动、旅行、礼物、审美、生活习惯；喜欢什么、为什么、不喜欢什么 |
| 性格与行为模式 | 主动性、表达直接程度、计划/行动、责任感、好奇心、适应与拒绝方式；体现在哪些行为中 |
| 情绪模式 | 触发情境、表达、恢复方式、需要的支持；不诊断、不把一次情绪固化成性格 |
| 价值观与决定 | 工作/金钱/家庭/独立性、公平、信任、风险与长期目标；不同选择中的取舍 |
| 聊天习惯 | 用词/口头禅、称呼、短句连发/长文、语音/表情使用、话题发起/回应、提问、解释、幽默、结束方式；双方分别描述 |
| 约定词义与语用 | 原句、约定/解释过程、双方理解、字面与实际意思、使用条件、回应期待、例外、有效期及后来修订；区分明示约定和推测 |
| 互动节奏 | 联系/回应的时间与场景、忙碌说明、未回复与后续补答；只基于可靠时间记录，不把延迟直接当态度 |
| 关系与边界 | 交往/合作方式、信任、信息/时间/工作边界；亲密身体或婚育仅在相关场景分析 |
| 群聊角色与协作 | 组织/协调/答疑/求助/参与等可见角色，与本人及其他成员互动；规则和角色是否变化 |
| 事件与承诺 | 工作/学业/家庭等重要事件、具体约定、完成证据、取消或变更、开放事项 |
| 演化与反证 | 与此前月份相比的新增、延续、改变、例外、矛盾；变化点及后续是否维持 |

每个维度给出“有证据结论 / 查过但没有足够证据 / 尚未分析或来源缺失”之一。
区分“没有新变化”和“没有任何偏好”。已有稳定偏好可简短引用前版，新增偏好
须明确记录；不能只写“喜欢旅游”“较敏感”“希望被理解”等空泛标签。

偏好区分明确自述、重复主动选择、仅分享、代他人购买、开玩笑及一次尝试。
例：“喜欢某种口味，重复主动选择，近期仍提及；避开另一种口味”比“喜欢美食”
可用。一次购买不能直接证明喜欢，更不能补造价格、颜色或品牌。

性格结论要写“在什么场景下，通常做什么，存在什么例外”。多条独立情境支持
推断；同一争执拆成30条消息仍只算一个情境。区分自己说的性格、实际行为和
Agent解释；检查反例及时间变化，避免只用冲突片段描绘一个人。

### 按场景选择重点

| 场景 | 更细的检查方向 |
|---|---|
| 同事/工作群 | 项目、交付、负责人、deadline、决策、术语、协作与工作边界 |
| 客户/业务联系 | 需求、方案、报价/约定、变更、跟进、交付和正式程度；不假定成交 |
| 朋友/兴趣群 | 共同话题、活动、具体喜好、分享/互助、社交边界和玩笑语境 |
| 家人/家庭群 | 家庭事务、照顾安排、分工、时间/金钱/个人边界与沟通方式 |
| 伴侣 | 一般会话维度之外，检查有证据的亲密关系节点及特定边界 |
| 未知/混合场景 | 先分析可观察事项与表达，保留场景候选，不强行填恋爱/客户字段 |

正文长度和 Claim 数随信息量增加，优先保留可复用事实、具体事情和聊天例子。
单月不必产出一份完整全局性格报告，但不能跳过会话里的偏好与行为线索。

### 约定语句、暗号与上下文含义

在同一份月度正文中保留“约定表达与语境”章节，会话汇总维护当前有效含义和
历史变化。分析普通朋友、工作、家庭和群聊中的术语、简称、称呼、暗号、共同梗、
省略表达和反话，不限于亲密关系。先区分两类约定：

- **语言约定**：双方/群内明确给某句话、词、表情或符号约定了特定含义。
- **行动约定**：约见、交付、提醒等具体承诺；按任务/事件记录条件、责任人和期限。
  同一句可同时涉及两类，但“理解意思”不等于“接受请求”，也不等于已经完成。

每个有证据的表达要说明：

| 项目 | 具体要求 |
|---|---|
| 原表达与变体 | 原句或必要短引、简称/拼写/表情变体；引用别人的话不能归为当前作者的约定 |
| 参与人和范围 | 谁提出、谁回应、对谁生效；按 conversation_id、成员及场景限定，不跨联系人复用 |
| 字面与实际含义 | 字面意思、明确解释或约定的意思；只给有依据的释义，保留不同语境下的候选 |
| 建立依据 | 提议、解释、对方明确接受或纠正，以及实际使用回合的稳定证据引用 |
| 触发条件 | 何时/对谁/哪种话题使用；否定、反话、角色扮演、引用、情绪和前后句如何影响意思 |
| 互动作用 | 在该回合是请求、拒绝、安慰、催促、暂停、结束、调侃还是其他作用；期待什么回应、是否实际出现 |
| 时间与变化 | 初次建立、首次可见、再次使用、撤销/改义和当前状态；首次出现不自动等于约定成立 |
| 反例与限制 | 对方没理解、明确否定、误用、换场景、只说一次或仅单方解释；需要确认的具体问题 |

详细分析采用“前文触发→原表达→接收方反应→澄清/后续→结论与反例”的回合链。
检索解释、改口、纠正和后续使用，不只统计词频。不固定每月几个例子；独立含义
和重要变化逐项保留，同义反复压缩，但保留能验证含义的完整回合引用。

双方明确约定可记录为 observed 的语言事实，用户明确确认用 confirmed；重复
使用仅支持 inferred 的场景候选，不自动升级为“双方约定”。第三人解释、网上
通用梗、一次笑声、默认沉默或亲密称呼不足以证明接受、同意或约定成立。
没有读到建立过程时写“本范围内观察到这样使用，建立时间未知”，不能补造。

同一句的含义可随语境不同。保留候选、条件和反例，禁止“一句话永久对应一个
意思”。以前的玩笑在本次真实争执中可能变成认真表达；从该回合读至语义结束，
必要时回查后续，不用旧词典覆盖明确的拒绝、边界或危险表达。图片/语音承载的
暗号未解读时标出具体缺口，不能根据周围文字虚构其图案、语气或含义。

SQLite 使用短 Claim，例如 claim_type=`conversation_expression`、conversation_id、
相关 subject/object、有效时间、状态和证据关系；完整释义、使用案例和反例留在
同一份 Markdown。当前 schema 没有专用“暗号词典表”，不得编造已实现的表或工具。
独立含义/改义可分别建 Claim，修订保留历史；无需每次出现都建新 Claim。
人际专属称呼不能生成可跨会话套用的全局人物性格结论。人物层只在有独立支持时
归纳解释、幽默、澄清或边界表达方式，具体语言约定仍引用所属会话版本。

回复仅检索当前消息实际涉及的有效释义及相关上下文；不加载全部暗号或凭历史
语言约定自动承诺、执行或发送。意思不确定且会影响回复时，先展开证据，仍不清楚
就在草稿中澄清，不把猜测当成对方意图。历史约定不能替代本次动作的显式确认。

### 人物层：跨来源综合

人物 Skill 按 Person 聚合：当前/历史资料、具体兴趣喜恶、性格与行为、情绪/
恢复、价值观/决策、沟通、生活/职业、边界、各关系中的角色及变化。保留私聊、
每个共同群或同类场景、资料身份表达、朋友圈表达各自的事实/推断/缺口。
输出应回答“有哪些具体特点、在何种情境体现、是否稳定、有什么例外和变化”，
而不是复制所有会话事件。重要个人事件进入简洁个人时间线，详细过程引用会话。

头像/签名/朋友圈只能先形成观察：内容是什么、何时可见、来源是什么；结合
多路独立证据再讨论偏好或模式。发了某景点不代表常去，转发某观点不代表赞同，
照片不自动证明在场。朋友圈发布日、资料观察日与所述事件日期分别保存。
只有私聊来源时标题/覆盖说明要限定来源，不以“全面人物”称之；有多路来源
也检查实际维度和反证，不凭数量宣布完整。self 与联系人适用同一聚合流程。

## 3. 具体事实与日期核验：共用规则和条件专题

针对用户要求和已出现的关键事实，跨相关历史检索候选并展开完整上下文。
共用检索包括约定/决定/截止/完成/取消/入职/考试/交付/见面，以及引用旧消息、
后来回忆和相对日期。生日线索出现或用户点名时检查生日/生辰/农历/阴历/阳历/
公历/身份证/提前过/补过；恋爱专题只在适用场景检查表白/接受/纪念日/周年等。
不在同事、客户或普通群里强制寻找恋爱节点，也不将合作确定解释为恋爱确认。

计划时间、承诺期限、实际发生时间和回忆/发布/观察时间分开。客户约定交付日
不等于已交付，入职通知不等于实际到岗；后续完成或变更应回写关联事件版本。

### 生日

分别处理每个人的真实生日、自述农历生日、公历生日、身份证登记日、某年实际
庆祝日及提前/补过。祝福日期不是自动等于出生日期，“明天/下周过生日”要结合
消息时间、上下文与历法。“九月份”不擅自填成9月1日，未知年份不推算年龄。
农历转换需有年份和可靠历法依据；不具备时保留农历原值，不强行生成公历值。

### 恋爱关系节点（仅适用时）

分别记录初次聊天、首次见面、表白、双方接受/正式确认、约定纪念日、见家长、
订婚/领证。不能用首次见面、亲密称呼或接吻替代确认关系。
原始确认对话优先核验；后来明确共同认可的纪念日也能确定纪念日期，但说明
来源是回忆而不是原始确认。周年/天数可提供候选，检验计算口径、闰日、前后文
和原始消息后再确定；不能只因算出一个日期就判定。

输出事实表：对象、事实类型、**可确定的日期/值**、历法或口径、消息记录时间、
结论依据、证据引用、状态/置信度。已知到日就写到日，不用月份或“可能”模糊化。
证据确实不足时说明查过哪些范围、出现哪些候选、差哪一步；不是默认写“未核定”。

明确原句可形成 observed 的具体结论，confirmed 仍保留给用户明确确认。
强证据和一般推断分别表达。用户指出漏检/错误后先重新检索来源，不机械沿用
旧报告里的 unknown；用户确认具体事实优先，同时保留历史证据及冲突来源。

## 4. 结论必须具体且可追溯

完整正文集中在 Markdown；SQLite 保存短 Claim、状态、日期、证据和版本关系。
一条结论至少表达对象、具体内容、场景/有效时间、依据及必要的限制。支持证据
和反证按引用关联，不在正文复制全部聊天或长篇元数据。

月度保留细节，人/会话汇总去重压缩，但不能把有依据的生日、偏好对象、正式
确认日期和行为例子压缩掉。人物事实、偏好、性格推断使用不同 claim_type，
observed / inferred / confirmed / unknown 不混用。模型不能编造精确概率；
说明置信度的来源是原句、重复独立行为还是推断，数值不是经过校准的测量。

事件只关联解释它的 Claim，不把该月份所有结论都挂到一个工作或关系事件上。
第三方经历、转发、引用、梦、角色玩笑与真实行为分开。疑似分手、辞职或怀孕
必须读到该段语义结束和必要的后续，不因单条命中关键词写成已经发生。

## 5. 变化分析须有时间锚点

用“此前表现→具体变化点→后续维持/反复/恢复→例外与替代解释”组织演化。
保留人物维度的变化链，不只保留工作/见面事件链。例如偏好新增或淡化、表达
更直接、行动与计划的差距、信任边界和冲突修复方式如何变化。
没有新证据就写延续或未知，不凭每个月标题制造成长曲线。

连续事件使用实际日期或有依据的日期范围；月初/月末只能作分析覆盖边界，
不能自动变成事件起止。因关系、工作或休假造成表达变化，需要列为解释候选，
不直接宣称人格改变或因果确定。消息量、回复间隔和词频不能独立衡量爱意。

## 6. 提交前的质量验收

- 逐块语义阅读无未说明缺口；仅全量扫描或重点片段分析不得标“全方位完成”。
- 双方维度已检查；偏好/性格不被事件概览替代，丰富月份不被固定配额截断。
- 用户点名的事实已专项核验；具体日期有明确口径且没有错归对象。
- 已检查约定词义、梗和省略语；重要表达有回合链、适用范围、确认依据与反例，
  单方解释和猜测未伪装成双方约定，语言约定未伪装成行动许可。
- 抽查事实、偏好和性格推断的引用，必须支持该结论；反例不能静默删除。
- 时间线有日期锚点、前后表现和持续性证据；月界不冒充事件日期。
- 事件详述与跨时间追踪通过 EVENT_ANALYSIS_STANDARD 的验收；重要事件过程、
  变更和结转可追溯，提交完整当前阶段时没有丢失此前有效进展。
- Markdown 完整且能支撑下游画像；覆盖数不替代质量，空泛套话不替代内容。
- 说明语义/媒体缺口、争议、实际成功上游版本与本次模板版本。

没有通过时继续针对缺口阅读/核验；无法继续时保存本地候选与进度，保留上一
成功版本，明确旧结果待复核，不提交“完整分析”或完成下游质量验收。
阅读进度复用现有数据库状态和本地候选；现有 coverage 只有证据数/水位等字段，
不伪造已经实现语义分块游标。简短覆盖说明可放同一份 Markdown，避免重复文件。

## 8. v7 动态多 Agent 分片、主体复核与全面双视图

用户明确授权多子 Agent 后，先统计每月消息跨度、条数和可读正文字符数；读取分片与月度产出是两种粒度。稀疏月份可合并数月或一年给一个 Agent，密集单月拆成多个连续时间块；不能机械每人一年或每人一个月，也不能为了预算丢弃月份或消息。使用 `python scripts/plan_analysis.py <monthly-input-dir> <work-plan.json>` 生成本地计划。默认每片 3000 条、60000 可读字符、最多 12 月与 12 条边界上下文只是可调整的初始预算，不是语义完整度阈值；超长单条继续展开，引用与未完回合回查相邻片。规划器只规划，不启动 Agent，不证明实际阅读。

每片交接稳定会话/身份、来源范围与输入校验值、月份及首尾消息引用、逐块实际阅读进度、媒体缺口和月度候选。跨月分片仍逐月独立输出，月内多片合并时去除边界重复，但保留独立事实和反例。协调者只读取紧凑交接与需核验的原文，不把全历史重新塞进一个上下文。

每月候选必须交给未编写该候选的主体/关系复核 Agent。复核不只看统计或摘要：展开支持事实与关系的原回合，检查代词、引用、转述、反事实及后续。错误归属先回查，再修订候选；未过复核不得作可信上游。协调者核对所有月份覆盖、跨月衔接与独立审核结果，串行领取和提交正式版本；孩子只读来源并写本地候选，不并行写正式库。不创建额外用户聊天、自动调度或跨任务消息。

### 执行效率与正文价值

全量阅读后直接形成一份月度候选，默认做一次集中独立审核，合并反馈后一次修订；后续只复查改动及其影响，不反复全篇阅读或逐项往返。审核优先处理人物/第三方归属、关键日期、关系变化、冲突/边界和实际完成结果。普通饮食、娱乐和通勤用有据短句归纳；不为低影响措辞和元数据格式反复阻塞进度。发现串月、系统性错归等实质问题才扩大复核范围。

正文写有用的信息：具体事情、喜好、性格与行为线索、双方社会关系、冲突过程和变化。同一事实集中一处，其他小节引用或综合，不重复展开。来源、未知方向和媒体局限统一在末尾说明；仅在影响某个重要结论时局部注明，避免每段重复“不能判断”“不代表长期性格”“不是诊断”。未出现的维度不机械填未知段落，覆盖检查留在简短交接中。阅读笔记记录新事实、精确证据和跨块未完事项，不逐条复述所有寒暄、表情或重复日常消息。压缩这些开销，不能缩减全部月份和可用正文的实际阅读。

### 全量请求与模型分工

用户要求全部历史时，覆盖名单必须包含固定来源的每一个月份；阶段性月份结果仅用于内部进度，不作为最终报告。只有全部月份完成语义阅读和独立复核后，主协调模型才做最终全量综合。子 Agent 按指定低阶模型阅读/复核，明确设置模型并使用不继承旧分析的初始上下文；不能默默改用主模型或复用旧结论。分配按实际条数、正文量和跨度均衡，可给一个阅读者数月或一年，但每块/每月真实进度独立保存。

主模型按成功月份与必要的跨月原文逐段综合，可先整理年份或时间段笔记再全量合并，保留独立事实、喜好对象、关系所属者、事件阶段、反例与变化；不能把“全量汇总”委派给低阶阅读者而只拼接其标题。HTML 包含最终综合、图文说明和全部成功月度细节，Markdown 保存同源完整分析。用量不足时保存范围、游标和缺口，不能把几个月或抽样报告称为全量交付，也不自行建立定时任务或升级模型。

输入记录、实际引用与语义阅读分别记账：提交的 `evidence_ids` 覆盖固定分析输入的全部稳定 ID，Claim/图示只关联实际支持证据，正文引用可以是子集；输入 ID 数量本身不证明读完。用户明确要求删除旧分析时，仅在预先核对的作用域内清理派生正文/图表/结论/版本索引，保留原始聊天、媒体、资料、身份、用户修正及来源核验；默认保留历史的规则不授权自动删除。

### 主体与双方社会关系

每项人物事实、喜好、经历、任务、事件和关系都分别辨认 `speaker`（消息作者）、`actor`（实际行动者）、`fact_owner`（事实所属者）、`relation_owner`（称谓或关系的所属者）以及 `mentioned_or_quoted`（被提及/被引用第三方）。说“我朋友明天面试”只支持该朋友的面试安排与说话人的转述行为；不能给说话人创建面试任务。联系人说“我妹妹喜欢猫”，偏好属于妹妹；本人说“我的师兄换工作”，经历属于本人的师兄，不能归给联系人。

必须分析 self 与联系人各自描述过的人际关系，包含亲友、同学、师兄师姐、同事、领导、客户和其他有证据的关系：关系的双方、所属者、来源、支持/照顾/求助/合作/分歧/边界、具体互动、变化及有效期。转述第三方的行为与说话人对其态度分别记录。关系结构不是仅分析 self↔联系人，也不是把被提及的人全归到联系人的社交圈。

“我朋友”“他妈妈”“师兄”等用 `scoped reference` 保留所属者、会话、上下文与时间；无稳定身份时不创建或合并 Person。同名、相同称谓不证明同一个人。代词不明保留未归属候选，不猜主体。第三方评价不等于被评价者已证实特征；没有具体行为证据不能给他全局画像。

### 紧凑完整 Markdown 与详细 HTML

最终分析覆盖事项/话题/任务、双方具体事实与日期、生活/学业/职业、兴趣喜恶、沟通习惯、行为、情绪、价值观、边界、约定表达、双方各自的人际关系、关系变化、事件过程、反例与未决问题；检查维度不意味着无证据也要填结论。不能仅交事件/冲突/性格三类。消息多、细节多的联系人尤其不得固定配额截断。

Markdown 是唯一正式分析正文，采用紧凑表达但保留全部独立结论、具体偏好对象、关系所属者、日期口径、有效期、例子与短证据引用；压缩冗余措辞而不是删除维度。HTML 提供用户可阅读的详细全量呈现，使用同一批已成功提交并独立复核的月度/会话/人物版本；可增加导航、分组和展示排版，不能凭空增添 Markdown 未包含的结论。若用户需要更多细节，先补充并重新验收 Markdown，再重新生成 HTML。

通过 `python scripts/build_analysis_report.py --conversation-id <id> --accepted-receipts <work/accepted_versions.json>` 生成完整报告。回执包含 `accepted_versions`（scope_type、scope_id、period、version）及 `source_months`；精确白名单只列本次成功复核的正式版本。渲染核对正式路径与正文 hash，不从工作区候选或未重审旧版拼接。该报告渲染正式 Markdown 全文，没有既有 Claim 仪表盘每类 500 条展示上限；不把 Markdown 当机器 Claim 数据源。

验收同时检查：每个来源月有明确成功版本或显式缺口；所有被检查维度可追溯到正文；丰富月度与第三方关系未被摘要吞掉；HTML 与 Markdown 的来源版本一致且正文无静默截断；争议、未知、媒体与阅读缺口可见。渲染成功不证明语义完整或主体归属正确，仍须 Agent 独立复核。旧 v6 与更早结果按受影响范围重读和主体重审，不只换模板号。


### 主题归纳与全历史变化的写作验收

本节用于月度线索进入会话、人物和关系综合时的归纳。覆盖清单是内部检查项，不是固定报告目录；主题数量由证据与用户关注决定，不固定为十一项。纠正主体、核对日期与保留局限用于保证事实准确，不作为正文的主要切入点。

**先确定主题要回答的问题，再归纳。** 每个主题内部先明确用户需要了解什么，筛选能共同回答该问题的事实，按时间和场景组织，再写有据的结论。生活/工作回答在忙什么、如何选择及怎样变化；喜好回答具体对象、共同点、差异和变化；社会关系回答各自与谁怎样相处及其影响；双方关系回答如何建立、日常怎样维系、重要转折及后续。标题和每段内容须匹配，不能因某件事显著或刚被纠正就塞进不相关主题。不同主题不强用同一种归纳方式，也不把一次事件改写成长期特点。

**性格与行为变化覆盖起点至终点。** 从固定历史范围内最早的相关证据建立早期基线，再比较中期与后期同类行为，注明变化出现时间及后续持续、反转或尚无后续。早期无相关证据时说明最早可观察时期，不补造基线；不能从中间挑一次事件起笔，却声称描述了全历史性格变化。没有变化证据时写长期延续或场景差异，不强造阶段或成长。跨期比较要对齐同一种表现及可比较场景；工作选择和恋爱争执不能直接拼成性格转变。

**归纳强度不能超过证据。** 一次事件支持该次行为；同一事件的多条消息、转述或多次提及只算同一证据。性格/稳定行为倾向需要跨时间的独立重复行为，并比较情境、对象和反例；跨场景均有支持才可扩大适用范围，只有私聊证据则保留私聊限定。小事可以作为重复模式的例子，不能凭一次忘回消息、购物、口味或抱怨直接判性格。极端或高影响事件单独记其行为和影响，也不自动证明稳定性格。用户自述按自述保留，不冒充已被行为验证。

先区分稳定倾向、具体偏好、处境反应与短期状态；考虑疲惫、忙碌、异地、角色变化等解释，不能把环境变化直接写成人格改变。价值观依据实际取舍及重复选择，情绪模式依据触发—反应—恢复过程；关系依据双方行动、日常投入及转折，不用冲突数量代表关系全貌。一次道歉、自我认识、承诺或积极行动分别记录，不等于已经持续改善；观察改善须有后续行为支持。矛盾说法按时期、情境或未解矛盾保留，不强行平均或为了故事连贯删去反例。

**先讲清事实，再解释模式。** 正文用自然称呼和具体动作说明情况，以代表性例子支持已建立的归纳；不先贴标签再找例子，不用“成长不同步”等抽象句代替解释，也不把零散事件清单当综合。正向互动、普通日常与冲突按其实际意义组织，不因审核重点而只从冲突切入；无需人为等量。归属纠错和不确定说明集中在来源附记，只有实质影响当前理解时局部说明。

综合交付前集中检查：主题是否回答用户的问题、例子是否支持归纳层级、时间是否覆盖最早至最后相关证据、比较对象是否一致、反例及处境解释是否改变结论、承诺与实际变化是否分开、段落是否属于本主题。不符合时修订对应归纳并回查必要证据，不为措辞反复重读全部历史。按本节更新 Skill 不代表旧私人综合已重写或自动语义门禁已实现。

#### 四类主题的详细总结要求

以下要求约束主题的实际内容，不固定标题或篇幅；细节量随独立事实和过程的丰富程度增加。不能用几句标签或一张简表替代详细总结，也不为凑齐字段编造信息。

- **生活与工作**：分别描述双方各时期在忙什么，包括生活安排、学业/职业任务、居住和通勤、实际负担及重要选择。重要阶段讲清背景、可选方向、本人诉求与取舍、行动、结果和对后续生活/相处的影响，形成从早期到后期的连贯脉络。计划与落实用于说明阶段，不把本节写成承诺检查或未知清单；不能只列入职/搬家日期而省掉选择过程。
- **兴趣与喜好**：分别写具体喜欢和不喜欢的对象、内容或活动，保留有据的原因、使用/参与方式、实际尝试及情境限制。综合共同兴趣、差异、如何一起参与或协调，以及新增、延续、淡化和改变。不同作品、食物或活动有独立意义时保留，不一概缩成“爱娱乐/爱美食”。临时选择与稳定偏好可自然区分，正文先让用户知道具体喜好；没有相反证据时不反复强调“偏好不永久”。表格可辅助对照，不能取代有信息的解释。
- **人际关系**：分别梳理双方与家人、朋友、同学、同事/领导等实际出现的关系。讲清关系对象与所属者、互动方式、支持与照顾、求助/合作、期待与自主选择、分歧及随时间的变化，说明这些关系如何影响本人的生活、决定或双方相处。第三方故事只有能说明该关系或确有独立背景价值时纳入；不以第三方履历清单代替相处分析。归属准确是底线，正文应明确谁与谁怎样相处，不能主要写“不是谁的事情”。稳定身份未核时保留有范围的称谓，不强行合并。
- **关系与变化**：从最早相识/接触证据到最后可观察阶段，描述相处如何建立、双方怎样投入和维系、共同日常/活动、沟通与照顾、协商及重要转折。区分长期持续互动、具体阶段改变和偶发争执；对改变说明早期表现、变化点、后续实际行为。冲突还原原因、双方诉求、反应、修复与后续，但不拿几个争执概括全部关系，也不凭道歉宣布修复完成。正向和普通互动按实质意义纳入，与异地、工作、家庭等处境一起解释关系发展；双方差异不强行写成对立性格。

复核这四类主题时，检查是否能据正文具体回答“各自怎样生活和选择、具体喜欢什么、与谁怎样相处、两人如何发展到现在”。若只能读到核查声明、抽象标签、孤立日期或争执概括，即使引用无误也须重写。细节不足时回读对应成功月报及必要原回合，不能通过增加概括句补齐。与性格/行为归纳共用前述证据层级、时间比较与反例要求；详细不等于重复月报或复制全部聊天。

### v7 有证据的图文结合展示合同

详细 HTML 需要信息图与完整正文结合：实际日期/计划日期分开的过程时间线、self/contact 各自社会关系图、具体喜好差异和沟通/情绪/行为的场景变化图。每个节点、边或时间条目必须能对应成功 Markdown 既有结论和证据引用，图上保留 observed/inferred/unknown 状态、来源范围与时间精度；无明确变化不造曲线，不给人格、感情或关系强度打分。第三方图节点保留关系所属者/scoped reference，禁止同名/同称谓合并。

可生成本地 `visuals.json` 派生展示清单，包含标题、图类型、节点/边/时间条目、来源 Markdown 小节、evidence ID 与 ordinal_base、来源及正文 hash。它不构成新分析正文/独立 Memory，只指导渲染；正式版本成功回执核验后才允许展示，不借候选或未审核历史扩充图。原有本地图片/媒体仅在授权、稳定来源、内容实际核验后使用，不下载、不用未核实头像或猜定账号照片。没有可靠媒体时仍提供信息图和详细正文，不以无图片退化为短 Claim 列表。图表是正文的导航与解释，不能用图吞掉细节。

### 语音文字纳入完整消息分析

语音必须处理其实际内容：先由归档阶段提取原音频并用程序本地 ASR 转写，再按原消息时间、方向和稳定 message_id 放回原会话阅读。语音原文件与转写文字同时保留；XML、时长、消息条数和“语音”占位符不能替代语义阅读。不要求通过微信 UI 转文字。

阅读月度分页时检查每条语音的 transcription 字段，逐条阅读可用文字，结合前后回合分析事项、日期、喜好、边界、约定及关系变化。转写者不是发言人；作者、行动者、转述第三方和关系所属者仍分别核对。引用原始 message_id，需要定位时保留转写版本和片段起止秒数。

机器转写可能误识别姓名、同音词、否定、数字和日期。影响重要结论的疑点回听该片段并比较上下文；无法核实时局部保留原候选，不擅自润色成确定事实。文本能支持内容分析，不能仅凭文字推断原语音的语气、音量或声学情绪。

原音频已存、转写成功、转写已阅读、关键片段已核验是不同覆盖项。分别交接实际数量与缺口；某段语音未转写时不能称该段已完成内容分析。新转写或用户更正按受影响月份重新分析，再更新成功的会话/人物/关系综合与 HTML；不仅刷新页面，也不重复生成同一输入版本。未变更部分保留原成功结果。
