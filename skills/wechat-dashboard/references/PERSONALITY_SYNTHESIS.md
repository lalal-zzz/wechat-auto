# 性格画像与人格框架归纳

适用于有足够长期证据的会话综合、人物 Memory 及其 HTML；月报提供行为线索，不必每月重新判型。上游是已成功审核的全历史正文和用户自述，下游仍是同一份正式 Markdown 与派生 HTML。

## 要交付什么

性格章节回答“这个人通常怎样感知、思考、决定、表达、与人相处”，而非再次列出做过什么。先给一段可辨认、有差异的性格描述，再展开主要特质。事实是归纳的依据，不是代替归纳的正文；具体经历详见月报。

每项采用“特质名称 → 具体心理/行为倾向 → 长期表现与代表性依据 → 优势与容易遇到的困难”。例如“自主性强”须解释怎样形成判断、如何对外界要求作取舍；只写搬家、拒绝一次邀约，不算性格描述。不要机械填固定数量或用大量‘不能判断’挤掉画像。

区分信息处理、决策偏好、社交主动性、情感表达、责任与执行、自主/合作、压力反应等维度。共同口味不是性格；情境中的拒绝不等于低合作；喜欢拍照不直接推出S，学技术不直接推出T，漏回消息不直接推出P。比较跨月独立行为、反例与可用场景，避免用冲突作为全部依据。

变化另用早期→中期→最新说明同一特质怎样表现。可以是特质延续、表达更明确、环境改变或确有持续变化，不把职业进程或一次道歉写成人格转变。

## MBTI 或其他框架

用户需要人格框架时，提供可解释的候选与维度推测，而非回避为纯事实流水。MBTI四维分别说明倾向、依据、相反线索和定性置信度；只有各维支持足够才给单一类型，否则列少量候选或明确未定字母。用户明确自报/测评与聊天推测分开记录，自报也不自动证明行为归纳。

聊天推测标 `inferred`，写“更接近……方向 / 候选……”，不写成测评结果、确定事实或诊断。置信度说低/中/较高，说明影响判断的维度，不造百分比、分数、雷达图数值、认知功能堆栈或人格变型日期。重点是读者能理解的特质，不让四字母标签代替画像。

MBTI用于偏好讨论；最佳匹配需要本人核对，行为也受角色和处境影响。框架边界参考[官方说明](https://www.myersbriggs.org/unique-features-of-myers-briggs/is-the-mbti-a-test/)和[最佳匹配类型](https://www.myersbriggs.org/unique-features-of-myers-briggs/best-fit-type/)。不需要每次联网重新查询已有定义，遇到新术语/争议再核验。

## 呈现与验收

Markdown保存完整特质解释、依据、反例、时间变化和模型候选；HTML可用特质卡、四维对照表、可展开证据和阶段对照，让读者先看到归纳，再按需看例子。图表仅展示正式正文已有推断和置信度；避免把非测评推测画成确定得分。

验收：去掉日期和事件名称后是否仍有具体性格描述？特质是否能被长期证据支持而非套话？早期到最新是否比较同一倾向？模型候选的每个字母是否解释，弱维度是否保留未定？只增加MBTI标题、给流水账换标题、贴类型后挑例子都须重写。

修订范围仅为归纳方式且原月报完整可靠时，重读相关成功正文即可，无须重复全量源读取；发现证据错误或缺口再回查对应原回合。先提交新正式版本，保留旧版本，再生成同源HTML；页面渲染不能自行新增人格结论。
