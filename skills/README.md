# Skill 目录约定

本目录中的每个 Skill 都是独立文件夹，文件夹名与 `SKILL.md` frontmatter 的 `name` 完全一致。Skill 资源只从自身根目录引用，不能依赖 `../../docs` 或其他 Skill 的私有文件。

```text
skills/<skill-name>/
├── SKILL.md
├── references/       # 按需加载的详细规则、格式和示例
├── scripts/          # 随 Skill 分发的辅助脚本
├── assets/           # 模板、样式、图标等静态文件
└── agents/           # 可选的运行器配置
```

只创建实际需要的子目录。需要的参考资料放在该 Skill 自己的 `references/`；需要另一个 Skill 时，在正文中用其名称说明交接，不链接到另一个 Skill 目录。Skill 之间不能有跨目录的文件依赖。仓库运行时实现和 CLI 本身仍属于项目代码；它们可以由 Skill 按仓库工作目录调用，不复制 Python 包实现。

## `SKILL.md` 写法

- 正文使用简体中文。命令、路径、字段、API、数据库表名和 UI 原文保留准确写法。
- 按长期有效的逻辑功能要求组织：用途、触发条件、前置输入、执行步骤、输出/交接、失败处理和停止条件。
- 不给 Skill 自身、章节或模板起版本号，不堆叠更新日志。只在业务正确性要求时保留输入/输出版本、数据水位、父版本和 schema 兼容状态；这些是运行状态，不是 Skill 版本。
- `SKILL.md` 保持简明，详细材料放在当前 Skill 的 `references/`，脚本放在 `scripts/`，静态资源放在 `assets/`。入口明确说清何时读取每个资源。
- `name` 使用小写字母、数字和连字符，且必须与所在目录名一致；`description` 清晰说明功能和适用场景。
- 写明当前实际能力。计划中的功能必须标成计划/缺口，不得写成已经可用。

## 项目共用规则如何随包分发

微信架构、安全边界、UI 流程、分析质量、存储和数据联动标准由相关 Skill 的 `SKILL.md` 与 `references/` 维护。Skill 执行时只读取自己的随包资源，不跳出 Skill 目录；共用标准变更须同步实际依赖它们的 Skill 随包文档，并核对各目录内的相对引用。`docs/` 不再作为 Skill 执行规则的维护来源。私人运行状态和来源审计仍按仓库要求保存到本机忽略的 `docs/` 文件。
