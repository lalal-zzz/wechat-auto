# 共用页面、联系人定位与发送规则

规则版本：2；更新时间：2026-10-01。适用 Windows 微信 4.x。
这是仓库内所有 Skills 共用的静态说明，读取规则不会自动完成身份核验。
页面类型见 [UI_PAGE_CATALOG.md](UI_PAGE_CATALOG.md)，动作核验规则见
[ACTION_VERIFICATION_MATRIX.md](ACTION_VERIFICATION_MATRIX.md)。

## 联系人状态与历史保留

必须区分三种情况：自己通讯录中联系人消失、对方可能删除自己、仅删除了聊天会话。
它们不能互相推出。历史聊天仍在、头像仍在或搜索到旧记录，都不能证明当前好友关系。

| 状态 | 判断依据 | 动作与处理 |
|---|---|---|
| active/restored | 当前完整通讯录快照中存在稳定 username | 允许进入身份定位流程，不等于自动允许发送 |
| missing | 一次完整快照缺席 | 保存历史，暂停自动发送；检查同步覆盖、资料变化和当前 UI |
| inferred_removed | 至少三次不同完整快照缺席，跨度至少 24 小时 | 只标记推测消失，保留全部 Memory、消息、事件及证据 |
| confirmed_removed | 用户确认或明确、可归因的系统信号 | 停止自动发送；不得自动添加好友、探测发送或删除归档 |
| unknown | 数据源不完整、读取失败、目标类型或身份不明 | 不累计删除证据，停止外部动作 |

`MemoryStore.reconcile_snapshot`/`observe_presence` 已有完整快照比较、缺席计数与
恢复历史的基础实现。不能把 UI 搜索失败当成完整快照，不能重复提交同一快照增加计数。
好友关系信号的全版本归一化、发送前状态门禁与自动 UI 审计尚未贯通，见 WA-005。
尤其不能用发一条消息测试对方是否删了自己。

## 搜索入口的选择

1. 先只读解析当前账号的稳定 `username/wxid`；群使用 `@chatroom`。
2. 当前已打开的会话只有在稳定身份已核实、页面仍匹配时才能复用。
3. 新定位私聊优先走 **通讯录 → 联系人候选 → 资料核验 → 发消息进入聊天**。
   通讯录页面的搜索框也可能产生混合搜索弹窗，进入通讯录不代表结果全部是联系人。
   当前资料/个人朋友圈流程先确认个人“联系人”分组的标题与展开箭头，只在该分组
   下方选人；“新的朋友”、企业联系人、公众号/服务号是其他分组。列表未命中停止
   并交给图片复核，不再自动进入混合搜索兜底。用户明确使用搜索时仍需执行分区核验。
4. 主搜索可用于找会话，但必须识别当前结果分区、独立弹窗及目标类型，不能点第一行或回车。
5. 公众号、文章、小程序、聊天记录、网络搜索不属于普通联系人候选。
   `actions.open_search_content` 是网络内容导航，不能用于定位收件人。
6. 群聊要走稳定群身份核验；联系人资料流程不能替代群聊核验。

本地 `username` 与资料卡显示的微信号 `alias` 是不同字段。资料核验比对的是数据库
记录的当前可见 alias，不要求 wxid 必须显示在资料卡。没有可见 alias 时，必须使用另一个
已实现并验证的稳定身份关联；当前不能只凭昵称、头像或标题认证身份，无法关联时停止。

名称必须精确匹配，不接受“张三”匹配“张三工作群”。OCR 分区识别失败不是删除证据。

## 每次发送的完整条件

收件人的稳定 ID、会话 ID、目标类型、确切正文和上下文版本共同构成发送计划。
用户确认绑定这份计划；发送前重新核验页面、身份、输入区及正文，计划变化则失效。
必须核验联系人资料并回到同一聊天后再写入草稿，不能在资料页、搜索框或右侧网页输入回复。
动态输入框坐标来自当前截图，不能使用调整前的全窗固定比例。

动作回执分开描述：身份核验、草稿准备、提交动作、结果观察。发出 Enter 不证明
消息已送达。出现失败/拒收信号时保留失败状态，不能标为成功，也不能自动重发。
任何一次发送、表情、点赞、评论及联网媒体下载仍需要逐次明确确认。

## 定向发送的搜索路径

用户指定单个联系人发送时可以直接搜索；批量资料和朋友圈采集仍走个人联系人分组。
搜索词与候选完整名称分别核对，允许用前缀检索，但只接受“联系人”分区中精确唯一的完整名称。
“最常使用”、历史记录、群或网络建议不能自动充当联系人分区。
查询内容以当前可见主搜索框 OCR 为证据；网络建议首项仅可核对查询回显，不得选择它发送。
结果较多、网络回显不可见时仍重新读取主搜索框，不能依赖上次输入记录。

Python BasicSkill 提供 `select_search_result`、`verify_searched_contact_alias` 与
`send_current_verified_text`。这些方法不表示 MCP 工具已自动完成同一门禁。
私聊先选择精确联系人，打开聊天信息中的当前成员头像，核验归档 alias，再关闭资料卡和信息侧栏，
核对返回同一聊天及当前输入区。资料卡可为无 owner 的同进程 Qt 辅助窗；这项形态不能替代
明确的资料页、alias 和返回会话验证。独立搜索弹窗仍要求与主 HWND 的 owner 关联。
文件传输助手单独要求“功能”分区精确项、本地 `filehelper` 身份及确切聊天标题。

文字发送前拒绝覆盖既有草稿，核对确切正文，单次提交后独立观察新增右侧绿色正文气泡与正文清空。
左侧其他会话的同文预览不能参与新增消息计数。结果不足保持 unknown，禁止自动重发；
只读后续复核可以增加证据，但保留原回执，也不能宣称服务端送达。
表情入口与收藏标签的识别不证明素材身份。原始格坐标及旧目录坐标不允许发送；
必须将历史素材关联到当前帧的唯一格并验证结果，该发送链路仍待实现。

0.7.1：只有聊天/通讯录/发现的幂等导航可做有界恢复，每次完整重观测和重定位。
窗口尺寸在识别后变化时不投递旧点。新页面、歧义和弹窗停止；发送、关闭及菜单
切换不自动重试。WM_* 投递不等于点击成功；通用排错见 [UI_FAILURE_RECOVERY.md](UI_FAILURE_RECOVERY.md)，实际结果只记本机台账。

0.8.0 的窗口识别与 Agent 图片复核见 [WINDOW_NAVIGATION.md](WINDOW_NAVIGATION.md)。
图片复核绑定控件框、窗口与当前帧，120 秒内单次执行，只允许限定的只读导航。
发送、删除、评论、下载不在复核白名单中。Agent 不能复用截图坐标或绕过资料身份校验。

## 文字发送入口的运行时约束

`BasicSkill.send_text(contact, text, confirm=True)` 的 `contact` 必须是稳定的
username/wxid（系统会话为 `filehelper`），且与当前已核验收件人 lease 一致；
此入口调用 `send_current_verified_text`，不再按名称重新搜索后直接回车。
`reply.send_confirmed` 的 `contact` 必须等于确认会话的 `source_chat_id`，当前仅支持
direct 会话；会话/正文确认不能替代当前资料、alias 和输入区核验。
未观察到成功结果时不将草稿记为 sent；单次确认已消耗，结果未知不得自动重试。
这不表示收件人状态、新鲜度和全部发送实机矩阵已完成。

确认与消费采用带旧状态条件的原子更新；并发连接也只允许一个调用成功。
派发后观察异常、收件人/窗口/页面变化、输入区消失、遮挡或失败提示均不能证明发送
成功，返回 result_unknown 且禁止自动重试。unknown 不等同明确未发送。

所有依赖 open_chat 的后续输入、粘贴、引用、复制和资料入口先要求 opened=true；
仅准备了搜索或待选择结果时必须停止。该标记仍不等于稳定身份链路已完成。
群艾特和引用尚缺稳定目标、素材及结果验证。`send_mention`、`prepare_quote`和`send_quote`在任何UI动作前拒绝；confirm=True、opened=true或OCR识别“引用”菜单均不能放行。不得回退盲目Enter或复用未绑定帧/消息身份的调用者坐标。`prepare_mention`仅允许当前稳定本地群ID（@chatroom）并复用prepare_text的空草稿/身份/正文检查，返回mention_verified=false和selection_required=true；它准备的是待核验普通文字，不代表真正@成员。当前稳定群身份来源仍待实现/实机验收，不手造凭据绕过。后续仍需完整群成员选择、mention chip、引用消息ID/当前帧、引用预览及发送结果链路，拒绝测试不能充当功能完成。
文件/图片缺少预览核验时在提交前停止，不派发发送；详见下文附件准备限制。

`BasicSkill.prepare_text(contact,text)` 的 `contact` 必须是当前已核验收件人的本地 username，不能传昵称作为搜索目标。接口不再自动搜索；先完成稳定身份路线，再确认同一窗口、确切标题、无面板/覆盖/辅助窗口及空输入区。输入后重新观察正文，`prepared/success=false` 不能当成草稿已就绪；该接口不发送，也不自动清除或覆盖已有草稿。

`cancel_prepared_text(contact)` 仅清理同一 BasicSkill 实例以 `prepare_text` 成功创建并保存短期内存凭据的草稿；不是通用清空输入框。取消前与聚焦后均重新核验稳定收件人、确切正文、输入区几何及整区像素摘要，任一变化停止；光标闪烁也可能触发保守拒绝。凭据在执行尝试前消费，清除结果未知不重试。通过当前最后一处文字框定位末尾，按准备时保留的原始文字UTF-16长度执行有扫描码的定量退格；保留空格，不使用归一化正文长度，不依赖Ctrl+A选区。缺少原始正文、超过驱动次数上限或识别到媒体卡时拒绝；仅观察空正文后返回取消成功。

发送已有草稿必须独立明确确认该收件人与确切正文；`send_current_verified_text(...,confirm=True,use_existing_draft=True)` 仍要求新鲜稳定收件人核验，连续两次读取的正文均须匹配。此模式不清空、不覆盖、不重输；默认发送路径仍拒绝已有草稿。派发后结果未知不重复提交，本次授权不能扩展到其他正文或对象。

附件准备：`prepare_file`/`prepare_image` 的 contact 同样使用当前已核验的本地 username，不自动搜索。设置剪贴板前、转换后、输入区聚焦后须分别重读身份/页面与空正文，变化时禁止粘贴。`prepare_file`记录初始源文件大小/SHA256，粘贴后调用完整Copy身份核验，要求当前同一收件人、同一路径/大小/内容、有效新鲜卡片像素凭据且源文件仍未变，才返回prepared=true、identity_verified=true；失败返回prepared=false，保留未知草稿，不自动重试/清理。此成功仅证明准备阶段。`prepare_image`仍缺图片预览身份，prepared=false。`send_file`/`send_image`在任何UI动作前拒绝，准备成功、confirm=True均不能启用旧Enter路径；尚需独立发送前载荷/页面复查及发送结果验证。不得以准备或拒绝回归代替真实附件发送通过。

附件剪贴板在粘贴前必须再次读回核对：文件要求CF_HDROP完整路径列表一致，图片要求CF_DIB字节与当前本地图片转换结果一致。格式缺失、载荷变化或读取错误停止，不粘贴、不发送。该瞬时检查不能证明微信已加载载荷，仍须独立预览核验；OCR期间剪贴板可能被其他程序替换，不把先前setter成功当作持续有效。文本剪贴板日志不得记录正文。

空正文检查不得仅凭OCR字符串忽略输入。已知“按住鼠标语音输入文字”提示只有在当前截图中呈低对比度、发送按钮也为灰色禁用状态且无绿色启用背板时才作为占位；真实高对比度同文、混合正文、启用发送按钮或截图不可用仍按正文/未知保护，不覆盖、不清除。此规则不授权自动切换语音模式。

附件准备改走当前原生输入区菜单，不以WM_PASTE失败后自动重试。只有本实例刚打开的、120秒单次来源和唯一主窗拥有的菜单可用于动作；底层主窗使用PrintWindow重新核对收件人和空正文，不把弹窗遮挡文字当成草稿。必须唯一精确“粘贴”、匹配菜单几何与置信度，并在点击前再次核对剪贴板载荷；任何变化停止。底层菜单派发回执保持prepared=false；prepare_file仅在后续完整身份与当前卡片核验通过后升级，不按Enter、不自动发送。

`hover_attachment_card(contact,path)` 只为当前输入区唯一文件卡片候选请求提示层：稳定收件人、当前帧、名称完整或严格省略片段、精确B字节大小与OpenCV卡片边界共同定位。大小候选匹配支持精确整数B，以及K/KB、M/MB、G/GB、T/TB和显式KiB/MiB/GiB/TiB；缩放单位按显示精度容纳十进制/二进制及四舍五入/截断范围，只用于候选定位并标记size_display_approximate，不能推断精确字节或身份。当前实际客户端的具体大小格式须另行实机验收；最终仍要求Copy完整名称、精确字节与SHA256，重复候选拒绝。历史区、重复或不匹配候选停止。执行只发送WM_MOUSEMOVE，不点击、不删除、不发送；full_name_visible也不自动构成身份/内容核验，tooltip未出现时保持unknown，不允许物理鼠标回退。

`open_attachment_context_menu(contact,path)` 只在当前候选卡片打开菜单，不确认身份或选择命令。`copy_attachment_identity(contact,path)` 使用新鲜单次卡片来源、四项选择菜单、唯一高置信度“复制”及底层主窗再核验；在打开菜单前设置非敏感哨兵，菜单观察期间剪贴板序列变化即停止。复制后必须产生新剪贴板，单个标准CF_HDROP文件的完整名称、字节大小、SHA256与本地期望一致，且本地源未变，才返回identity_verified。缓存路径可不同但不能只凭旧剪贴板/截断名称。该证据不授权发送或删除，读取失败不重试、不打印私有路径；不使用微信私有剪贴板协议。

`cancel_verified_attachment(contact,path,confirm_discard=True)` 是单个未发送附件的明确取消，不是聊天消息删除或通用清空。需要同实例120秒内成功复制核验的完整名称/大小/SHA256凭据，单次消费；卡片几何/像素、当前菜单来源ID、收件人和其他正文须重新核对。仅本卡片当前菜单精确“删除”可执行，不选剪切、不SelectAll、不发送。后置检查卡片大小的矩形消失、其他正文和本地源文件仍保留；有其他卡片/证据不够时保守unknown，不重复动作。不能把缺OCR当卡片消失，也不能导入旧凭据认领未知草稿。调用者只可取消用户明确指定或本任务自建的附件。卡片之外存在正文时在派发前拒绝，不以事后检查代替保护；混合正文/附件取消尚未支持。

附件复制身份凭据还绑定Copy后重新观察的同一收件人、同一当前卡片边界及可用像素摘要。Copy后页面/卡片变化或截图失败不发凭据；取消前必须与该身份帧摘要一致，缺少摘要的旧凭据拒绝。该检查不代表图片或附件发送流水线已验收。

空OCR正文不单独证明输入区为空：当前发送按钮仍有绿色启用背板，或截图/按钮像素不可用时，稳定收件人输入区检查必须停止，不点击、输入、设置附件剪贴板或追加附件。此保护覆盖未被OCR读出的图片/贴纸等草稿信号，但不是完整媒体草稿识别；未覆盖主题和混合媒体仍须单独验收。

截图帧必须与当前窗口几何一致：PrintWindow位图尺寸不符或捕获期间窗口移动/缩放时丢弃；可见截图还须前台、可见性和最小化状态前后一致。GDI释放异常不得阻止其他资源的清理尝试。截图默认保存在data/screenshots，标签只能是单个文件名组成部分，留证不得覆盖既有文件，保存失败不保留半截PNG。离线合成测试不能代替真实主题/DPI/遮挡验收。

回复ContextBuilder的identity_scope仅描述归档关联，current_account_verified始终不能据此当作当前微信账号已核验。会话明确self角色优先；无绑定时只能采用唯一已知且活动的归档self（有多个已知self时即使仅一个active也须核对），私聊对方即使也是本人其他账号也不能当当前self回退。缺失/多重/失效绑定、错误或多余私聊成员须标requires_identity_review并计入requires_more_data，不加载无关人物背景。私聊对方须以会话source_chat_id精确匹配稳定本地身份；无Markdown也不关闭成员参数校验。身份范围进入上下文指纹；补齐或变更后重建草稿。该元数据不代表MCP已有自动身份/新鲜度门禁，不替代BasicSkill发送前核验与明确确认。

reply_context对current_messages中非空chat/source_chat_id/conversation_id声明逐项匹配目标会话，明确不匹配即拒绝；缺声明可保留候选正文，但须标requires_message_scope_review，不能称已核验当前消息。声明匹配不代表内容来源或新鲜度已认证。归档时间过滤支持Unix秒和毫秒；无法解析的时间保留候选并标requires_time_review，remaining_count=0不清除该缺口，不应循环空翻页。上述范围/时间信息进入指纹并影响requires_more_data，但不替代未实现的完整MCP自动新鲜度门禁。


## 用户明确要求删除未发送的文字草稿

Python BasicSkill提供`delete_verified_text(contact, text, confirm_discard=True)`，仅用于用户已明确批准的当前确切文字草稿。它重新核验稳定收件人、正文、当前输入区和文字位置，聚焦后再次检查，再通过既有HWND驱动退格并验证空输入区；正文变化、识别到媒体卡或不能验证时停止。该入口不依赖旧的准备草稿lease，不删除聊天历史、不发送消息，也不代表MCP已新增同名工具。既有`cancel_prepared_text`仍只处理同一实例拥有的未变化草稿；不能通过伪造lease绕过任一门禁。


## 图片草稿的核验与清理

`prepare_image` 已派发粘贴但未完成预览身份验收时，必须返回 `prepared=false`、
`success=false`；不能仅凭粘贴动作成功放行发送。

Python BasicSkill 的 `cancel_verified_image(contact,path,confirm_discard=True)` 仅用于
用户明确指定或本任务自行创建的单张图片草稿。稳定收件人、当前输入区和源文件
须重新核对；动态缩略图匹配只提供候选，不证明图片身份。低辨识度、重复候选、
其他正文、窗口/源文件变化或不能验证时停止。

图片选择菜单与文件选择菜单不同。图片初始菜单须观察到剪切、复制、另存为与编辑；复制后也可能变为剪切、复制、粘贴、删除的选择菜单，两种均须完整核验；
仅在本次图片菜单来源绑定后，先执行原生复制，并要求剪贴板位图或单个本地图片引用解码后的完整RGB尺寸/像素
与本地源图完全相等（多引用、非图片或像素不符拒绝），再核验当前画面、菜单、剪贴板序列与源文件，才能对该图片
执行原生剪切。最后要求输入区为空、剪切所得图片仍与源图一致、本地源文件不变。
这不是剪切源文件，不点击另存为或编辑，不发送；结果未知不重试。文件附件取消
继续仅使用其原菜单精确删除，不因图片规则放宽。该Python动作不代表新增同名MCP工具。


### 完整图片准备回执

`prepare_image` 在粘贴前记录源文件哈希，并核对标准剪贴板DIB载荷；粘贴后组合
`copy_image_identity`，执行当前缩略图/收件人/原生菜单检查、非敏感哨兵及新剪贴板
序列检查、完整RGB尺寸/像素比对，再核验当前图片帧、源文件和同一收件人。
只有全部成功才返回 `prepared=true`、`identity_verified=true`、`success=true`；
源文件、收件人、剪贴板或当前帧变化，以及复制失败，都不能放行。

`copy_image_identity` 仅原生复制，不剪切、不发送；它与图片清理共用一套核验实现。
准备成功不是发送授权，也不代表 `send_image` 的提交和发送结果验证已经实现。
低辨识度或不能唯一定位的图片仍拒绝，不以旧剪贴板或缩略图相似度替代完整身份。


## 完全一致帧的OCR复用

Vision可在单个实例内仅保留最近一次非空OCR结果。复用前仍读取当前截图，逐字节
比较实际送入OCR的RGB像素，并要求引擎实例、原图尺寸、裁剪区域、窗口尺寸参数、
缩放参数，以及当前HWND/PID/class/owner/窗口矩形/客户区矩形/DPI完全一致；窗口
元数据不可读、推理/命中期间变化、空结果或异常均不缓存。坐标不是按尺寸套用。

只复用纯OCR字框且返回独立副本，不复用页面、几何、动作回执、确认或身份凭据；
当前图片、页面分类及几何仍重新观察。任一输入RGB像素变化都会重新OCR，不掩盖光标或
用户编辑。缓存仅单帧本机内存，不写入磁盘、不跨Vision实例共享私人结果。
